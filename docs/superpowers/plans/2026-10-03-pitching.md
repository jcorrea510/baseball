# Pitching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In Quick Game and League the player pitches the computer's half-inning (aim + timing ring from a pitcher's-eye camera), against a computer batter that swings through the same physics, with stamina, a one-tap bullpen, a Sim button and real League pitchers.

**Architecture:** Three new pure logic modules (`game/pitching.js` your pitch, `game/cpuBatter.js` his swing, `game/cpuRunner.js` his base running) plug into the engine, which learns which side is batting each half; the pitched-half methods live in a new `game/pitchingHalf.js` installed onto the `Engine` prototype so `engine.js` does not grow past what one person can read. Everything after the swing decision (`computeSwing` -> `bat.js` -> `ballistics.js` -> `planPlay` -> `rules`) is the existing, audited code. Presentation adds a camera preset, `render/pitchAim.js` and HUD pieces; the League gains pitchers in `mlb.js` / `season.js`.

**Tech Stack:** Vite, vanilla JS (ES modules), three.js, Vitest, Node scripts, headless Chrome QA scripts (playwright-core).

**Spec:** `docs/superpowers/specs/2026-10-03-pitching-design.md` (read it first; this plan argues from it). Also read `CLAUDE.md` (architecture, conventions, coordinates, commands).

## Global Constraints

- Every tunable number goes in `src/config.js` with a plain-English comment; no magic numbers in logic.
- Logic modules (`src/game`, `src/physics`) never import three.js or touch the DOM.
- Timing never depends on frame rate: engine time only; inputs take a `sinceUpdate` like `swingPressed`.
- Renderers read engine state and never change outcomes. Randomness in outcomes only from the engine's seeded rng (`this.rng`), never `Math.random` and never the bot's rng.
- Text on screen is labels only (PERFECT / GOOD / OK / WILD, PAINTED, Bullpen, Sim, pitch names) - no explanatory sentences.
- `season.v` stays 2 (progression drops a league with another version); new League data is added on load by `ensureStaff`.
- The player's batting is unchanged: camera, aim, help, difficulty numbers, Derby. `tests/feel.test.js`, `tests/hrrate.test.js` and `node scripts/feel.mjs` numbers must not move.
- The computer batter never uses the player's batting help (`d.windowScale`, `d.aimAssist`, `d.batBonus`, `d.contactWindow`).
- The computer's at-bats never change `engine.stats` (your batting) or your players' `lines`.
- One topic per commit; commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on `main` (`git fetch` first). Push at the end of each stage after `npm test` passes; confirm the GitHub "Check the game" run is green (`gh run list --branch main --limit 1`).
- On the owner's Windows PC the full `npm test` times out some long simulation tests; run touched files with `npx vitest run <files> --no-file-parallelism` and treat the CI run as the verdict (see CLAUDE.md).
- Smoke test (`npm run build && npm run smoke`) whenever startup, menus, `index.html` or the HUD flow the smoke test clicks through changes (tasks 9, 10, 20).

## Review Focus

1. **The computer walks off on the road.** A League road game (`playerSide: 'top'`): bottom of the last inning tied, the computer scores - the game must end at once as a loss (no hang waiting for a third out, no extra pitch). Test in Task 6.
2. **Sim pressed at an awkward moment** (during the delivery, while a ball is in play, between batters). Expected: it takes effect at the next point the half can be handed over (the current pitch / play finishes normally first), never double-counts the pitch, and the half ends with three outs (or the game ends). Test in Task 8.
3. **Left-handed pitchers.** Arm side is +x for a lefty and -x for a righty as the catcher sees it: an early WILD tap sails up and to the ARM side for both, mirrored. Test in Task 1.
4. **Pausing mid-delivery** (pause menu, tab hidden, the window losing focus). The ring and the delivery only move with `engine.update(dt)`; a tap after a pause is graded against engine time, so pausing never turns a pitch WILD by itself. Test in Task 6.
5. **The bullpen at its edges:** a pitching change mid-count keeps the count; a pitcher taken out never comes back; with no relievers left the Bullpen button is disabled and `bullpen(id)` refuses; Sim's automatic change at 15% stamina only uses an unused reliever. Test in Task 15.

describe('your pitch', () => {
  it('grades the tap by ms from the moment the ring meets the dot', () => {
    expect(gradeTap(0)).toBe('perfect'); expect(gradeTap(-40)).toBe('perfect'); expect(gradeTap(41)).toBe('good');
    expect(gradeTap(90)).toBe('good'); expect(gradeTap(-91)).toBe('ok'); expect(gradeTap(160)).toBe('ok');
    expect(gradeTap(161)).toBe('wild'); expect(gradeTap(null)).toBe('wild');
  });
  it('rings run faster for harder pitches, worse control and a tired arm', () => {
    const base = ringTiming(P(), 'fastball').time;

    expect(ringTiming(P(), 'curveball').time).toBeLessThan(base);
    expect(ringTiming(P({ ctl: 99 }), 'fastball').time).toBeGreaterThan(base);
    expect(ringTiming(P(), 'fastball', 1).time).toBeCloseTo(base / 1.35, 5);
    expect(ringTiming(P(), 'fastball').hitAt).toBeCloseTo(0.75 * base, 5);
  });
  it('a perfect pitch is full speed and lands near the dot; ok is slower and misses further', () => {
    const aim = { x: 0.5, y: 2.2 };
    const perf = many(400, (rng) => throwPitch({ pitcher: P({ vel: 99 }), type: 'fastball', aim, errMs: 0, fatigueF: 0, rng }));
    const ok = many(400, (rng) => throwPitch({ pitcher: P({ vel: 99 }), type: 'fastball', aim, errMs: 150, fatigueF: 0, rng }));
    const miss = (a) => a.reduce((s, p) => s + Math.hypot(p.target.x - aim.x, p.target.y - aim.y), 0) / a.length;
    expect(perf[0].speedMph).toBeCloseTo(100, 5);
    expect(ok[0].speedMph).toBeCloseTo(94, 5);
    expect(miss(perf)).toBeLessThan(0.1);
    expect(miss(ok)).toBeGreaterThan(miss(perf) * 3);
  });
  it('early taps miss up and to the arm side, late ones down and glove side - mirrored for a lefty', () => {
    for (const hand of ['R', 'L']) {
      const arm = hand === 'R' ? -1 : 1; // arm side in x as the catcher sees it
      const early = many(300, (rng) => throwPitch({ pitcher: P({ hand }), type: 'fastball', aim: { x: 0, y: 2.5 }, errMs: -70, fatigueF: 0, rng }));
      const late = many(300, (rng) => throwPitch({ pitcher: P({ hand }), type: 'fastball', aim: { x: 0, y: 2.5 }, errMs: 70, fatigueF: 0, rng }));
      const avg = (a, k) => a.reduce((s, p) => s + p.target[k], 0) / a.length;
      expect(Math.sign(avg(early, 'x'))).toBe(arm); expect(avg(early, 'y')).toBeGreaterThan(2.5);
      expect(Math.sign(avg(late, 'x'))).toBe(-arm); expect(avg(late, 'y')).toBeLessThan(2.5);
    }
  });

    const hangs = w.filter((p) => p.wildKind === 'hang'), sails = w.filter((p) => p.wildKind === 'sail');
    expect(hangs.length / w.length).toBeGreaterThan(0.4); expect(sails.length / w.length).toBeGreaterThan(0.4);

  });
});

- [ ] **Step 4: Implement `src/game/pitching.js`.** Rating maps are linear between 1 and 99. `throwPitch`: the speed is `lerp(velo, vel)` + the type's `speedDelta` (heater: `cfg.pitch.heaterSpeed` scaled by the same share) x the grade's `speed` - `tireVelo x f`; `movementScale` = `lerp(stuff, stf)` x the grade's `brk` x (1 - `tireBreak` x f); the miss is gaussian with sigma = the grade's `miss` x (1 + `tireMiss` x f), plus a directed part for the tap: `dir = sign(errMs)`, arm side x = `hand === 'R' ? -1 : 1`, offset = `min(|errMs|, 250) / 250 x miss` toward (`-dir x arm`, `-dir`) in (x, y) - early (negative) goes up and arm side.
