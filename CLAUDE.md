# CLAUDE.md - Sandlot

Browser baseball batting game ("spiritual successor to the old doodle baseball game", far more polished). **Vite + vanilla JS + three.js.** Everything (textures, sounds, people, crowd) is generated in code - there are no asset files except the owner's optional umpire recordings. The owner does not code: they judge by playing, so keep commands and explanations plain-English and never leave TODOs.

Modes: **Quick Game** (3 innings vs the computer, extra-innings runner on 2nd, walk-offs), **Home Run Derby** (10 outs, batting-practice pitches), **Practice** (pick the pitch speed). Three levels: Rookie, Pro, All-Star. The player only bats; the computer's half-innings are simulated instantly.

## Commands
- `npm run dev` - dev server (http://localhost:5173)
- `npm test` - Vitest (`tests/*.test.js`, pure logic, no browser)
- `npm run build` - production build to `dist/`. The base path comes from `scripts/resolveBase.mjs` (see Deployment). `vercel.json` holds the Vercel settings.
- `npm run smoke` - (after a build) serves `dist/` under a `/<repo>/` sub-path and drives headless Chrome: must reach the title screen and survive a real click-through (Settings with a volume slider, Credits, Esc back twice, Play, how-to, a setting, Quick Game, pause, the zone / pitch-guide / ring switches, one tap on Quit only arms it, resume). Console warnings count as failures. Eight scenarios: (1) built game reaches the title, (2) menus with real clicks, (3) Vercel-style build served at `/`, (4) default build (`./` base) served from another folder, (5) a build made for the wrong base served at the root of a non-GitHub host -> readable error that does not mention GitHub, (6) WebGL blocked -> the "couldn't start 3D graphics" screen, (7) the raw un-built source (what GitHub serves for "Deploy from a branch") -> the "game files didn't load" screen, (8) a pretend recordings folder (`SANDLOT_UMPIRE_DIR`) -> files found by the build, downloaded after the first click, played, and nothing 404s. `CHROME_PATH=/path/to/chrome` picks the browser (in this sandbox Playwright's Chromium is at `/opt/pw-browsers/chromium`; CI uses the runner's Chrome).
- `npm run sim` / `node scripts/sim.mjs [games] [timingSdMs] [difficulty]` - headless bot playtest with stats (win %, AVG, HR, outcome table by contact grade). Use it after changing physics/fielding/contact numbers.
- `node scripts/pitchmix.mjs [pitches]` - where the computer pitcher throws, per difficulty (share of strikes, hittable, out of reach, in the dirt, high heat...).
- `node scripts/hrrate.mjs [swings] [derby|quick]` - home run % for perfect and good swings by level (straight / pulled / opposite, early vs late). Derby targets: perfect ~70-85%, good ~25-40%; `tests/hrrate.test.js` guards the bands. Derby-only batting help lives in `modes.derby` (`evBonus`, `goodQuality`, `goodLaunch`, `pullBonus`, `pullSpan`) and reaches `computeContact` through `derbyBatting(cfg)` - the Quick game numbers are separate.
- `node scripts/guidecheck.mjs [pitches]` - how readable the pitch guide is per level. `node scripts/guideqa.mjs <dev-server url>` checks it in the real game and saves screenshots to `qa-output/`.
- `node scripts/landingqa.mjs <dev-server url>` - checks the landing ring in the real game (spot vs where the ball really lands, shrink, hide, switch); screenshots to `qa-output/`.
- `node scripts/groundcheck.mjs [plays]` - plays thousands of ground balls through the planner and the referee (`src/game/playAudit.js`): every out must have a fielder ON the bag WITH the ball before the runner, thrown at the bag. Prints who records the outs; must say "no problems". `node scripts/groundqa.mjs <dev-server url>` (needs `npm run dev`) forces grounders to every infielder in the real game and measures the picture at the moment of the out.
- `node scripts/wallcatch.mjs [balls] [bandFeet]` - hits many fly balls that come down in the last 30 ft before the wall and reports the catch rate on the CATCHABLE ones by an independent yardstick (walks along the ball's flight and asks every fielder, with the game's movement model, whether he can be within glove reach while the ball is below `reachHeight` and inside the park). Must be 100% (`tests/wallcatch.test.js`). `node scripts/wallqa.mjs <dev-server url> [flies] [--wall|--leaps]` checks the PICTURE of catches in the real game.
- `node scripts/wallcheck.mjs [plays]` - plays thousands of deep balls through the planner and reports any fielder outside the ballpark (`tests/wall.test.js` guards it).
- `node scripts/tune.mjs [samples] [sdMs] [difficulty]` - hit/out/HR rate by batted-ball type (for tuning fielders).
- `npm run umpire -- <call> <file or link> [--take b]`, `--list` - the owner's way to add/swap an umpire recording (see "The umpire's sounds"). `node scripts/umpirewav.mjs [folder] [rate] [variants] [prefix]` renders every built-in call to .wav files (for listening or analysis outside the game).
- `node scripts/hudqa.mjs [sizes] [url]` - forces every HUD pop-up on at once in each mode and prints any two boxes that overlap (must print "no overlaps" everywhere; checked at 20 sizes 360x780 ... 1920x1080). `node scripts/playqa.mjs [url] [sizes]` - plays every mode to the end from the title with real clicks/taps and one real swing, reports results and any console error. `node scripts/leakqa.mjs [url]` - starts/quits 12 games; the shape/texture counts must stay flat (216/31). `node scripts/mixcheck.mjs [url]` - loudness of every sound through the real mix.
- `node scripts/brand.mjs [dev url]` - remakes `public/favicon.svg`, `favicon-32.png`, `apple-touch-icon.png`, `icon-192/512.png`, `og-image.jpg` (1200x630 share picture: the real title screen + logo) and `site.webmanifest` from `src/ui/logo.js`. Commit the outputs.

## Architecture (three layers)
1. **Logic (no graphics, unit tested)** - `src/game`, `src/physics`
2. **Presentation** - `src/render` (three.js), `src/audio`, `src/ui` (DOM)
3. **`src/app.js`** wires them together (input, time control, engine -> effects/audio/UI hooks, menu navigation). `src/main.js` boots it: `new App(...)` only stores the canvas, `await app.init(report)` builds everything in stages and reports progress to the splash. `src/config.js` holds ALL tunable numbers. `src/util/` = `math.js`, `rng.js` (seedable).

Module map:
- `src/physics/`: `field.js`, `pitch.js`, `ballistics.js`
- `src/game/`: `engine`, `timing`, `contact`, `fielding`, `fielderMotion`, `playAudit`, `runnerMotion`, `rules`, `pitcherAI`, `aiHalf`, `pitchGuide`, `landing`, `progression`, `teams`, `bot`
- `src/render/`: `scene`, `environment`, `stadium` (+ `perimeter`, `crowd`, `scoreboard`, `textures`), `rig`, `poses`, `actors`, `cameraRig`, `ball`, `effects`, `pitchGuide`, `landingRing`
- `src/audio/`: `audio` (engine), `umpireVoice`, `voiceRender`, `formants`, `umpireFiles`, `umpireNames`
- `src/ui/ui.js` + `src/style.css` + `src/ui/logo.js` (the logo and badge as SVG strings, pure)
- `scripts/` (Node tools and QA, listed under Commands), `tests/` (26 files, one per module or topic), `public/` (icons, share picture, manifest, `sounds/umpire/`)

### Coordinates (used by every module)
Feet. Origin = back tip of home plate. `+x` = right-field side (screen-right from behind the plate), `-z` = toward the pitcher / center field, `+y` up. Spray angle 0 = center, negative = left field. The camera sits behind the plate at `+z`. Person-local axes: `+z` = the way they face, `+x` = their LEFT hand.

### Logic (`src/game`, `src/physics`)
- `physics/field.js` - bases, fence curve, fair/foul test, grandstand profile, the ballpark outline for the wall code, and the dugouts (`dugoutSpot(sd)`, `DUGOUT`): their front rail is part of the outline, so fielders never run through a dugout, and `render/stadium.js` draws them at the same spot.
- `physics/pitch.js` - `buildPitch`: a pitch is a constant-acceleration path solved to hit a chosen spot at the timing plane (`pitch.contactZ`). Movement (break/hop) is visible from release. `zoneRatio` = how far a spot is from the middle of the zone (1.0 = the edge).
- `physics/ballistics.js` - `simulateBattedBall`: fixed-step (1/240 s) flight with gravity, drag, backspin lift, sidespin hook, bounces, rolling, wall, stands. Returns samples; the picture replays them (frame-rate independent). Also `judgeFairFoul`.
- `game/timing.js` - timing windows (perfect/good/early/late/miss) and `resolveSwingTimes`. **Error = bat time - ball time (ms)**. The visual contact time is clamped near the ball so bat and ball always meet.
- `game/contact.js` - pitch location + timing -> exit velocity, launch angle, spray, spin (`computeContact`). A pitch beyond `timing.chaseRatio` caps contact at "weak"; beyond `timing.reachRatio` the bat whiffs.
- `game/fielding.js` - `planPlay`: given the ball flight + runners, decides catch / groundout / hit / extra bases / double play / sac fly and returns a **plan** (a timeline: fielder paths, throws, carries, runner moves, events, `endTime`). Nothing in it is random (repeatable). `createDefense` holds fielder speed/reaction.
- `game/rules.js` - counts, outs, walks, force advancement, `applyPlay`, innings, extra innings (runner on 2nd), walk-offs, line score. Pure functions on a state object.
- `game/pitcherAI.js` - what to throw (type mix by difficulty/count, tells) and where: each pitch is 'heart' (in the zone), 'edge', 'chase' (tempting, out of the zone) or 'waste' (way out of reach: in the dirt, high heat, way off the plate); `difficulty.<level>.locations` are the odds, the count shifts them (strikes with three balls, chase pitches with two strikes), and every kind of pitch misses the way it moves (a slider aimed off the plate starts as a strike and breaks out). Derby is all hittable. `game/aiHalf.js` - the computer's half-inning, simulated instantly from odds in config (`difficulty.<level>.ai`).
- `game/engine.js` - **the orchestrator**: phases `ready -> windup -> pitch -> (play) -> result -> ...` (the next windup also waits for `fieldersSetAt`: when a play ends the engine works out, from the plan, when the pitcher and catcher are back on their spots (`fielderBackTime`, using the same jog the renderer shows) plus `pace.pitcherSet`; show-only support runs are capped to the length of the play so this stays quick), swing handling (`swingPressed(sinceUpdate)` - pass the seconds between the last update and the real input event so timing ignores frame rate), Quick/Derby/Practice rules, events (`on('contact')`, `'playEvent'`, `'result'`, `'pitchCall'`...). `engine.pitchOverride` lets tests throw exact pitches.
- `game/progression.js` - localStorage (always try/catch, in-memory fallback; key `sandlot.save.v1`), career stats, high scores, unlock milestones. `resetStats()` clears career + high scores only (settings, unlocks, equipped stay); `fresh` = nothing was saved before (first visit). `game/teams.js` - original teams/uniforms/bats/names. `game/bot.js` - test bot.

### Fielder movement and diving
- `game/fielderMotion.js` (pure logic) is the ONE movement model. `covered`/`timeToCover` (a fielder heading for cruise speed vc covers vc*(t - A*(1-e^(-t/A))) ft, A = `fielding.accel`) are used both by the planner's "can he get there?" search and by `planRun`, which the renderer plays back - so what the planner promises is exactly what is drawn. `planRun` = react, accelerate, cruise, brake; with time to spare he arrives early and waits, on a tight play he arrives on time at speed and eases to a stop past the spot (a running catch). `Mover` (braking curve, arrival radius, retarget threshold) drives everything that is not a planned run (jogging back).
- **The third out ends the play** (`endInningStop` in fielding.js): when a play makes the third out, every runner still going gets `move.stopAt` (third out + `runner.easeUpReact`); `runnerState` coasts him to a stop along his route (`runner.easeUp`), no `safe` call is made for a base he never reached, and `plan.endTime` is cut to shortly after the out. `tests/thirdout.test.js`.
- **Covering a base** (`coverOptions` in fielding.js): an out at a base only exists if somebody is on the bag with the ball before the runner. The options are (a) a throw to a covering fielder - the throw is timed to reach the bag when he does, so the out is made at `max(when the throw could arrive, when he can get there)` (`cover.start`, `cover.minSpeed`, same run model as everything else) - and (b) the fielder with the ball carries it to the bag himself (`cover.selfDistance`, `cover.selfBonus`, starts when his fielding run has stopped). Candidates come from `coverCandidates` (first base: the 1B himself, else the pitcher, then the 2B when the 1B has the ball; second: the middle infielders; third: 3B/SS; home: C); the usual man gets `cover.traditionBonus`. If no option beats the runner, there is no out (a hit). Force plays, double-play relays and hit plays (`finishHit`) all use it, and `settleThrows` never re-aims a throw at a base. Do not add a new way to record an out without going through it - `auditPlan` (also run by tests/groundouts.test.js over thousands of plays) will flag it. There is no separate "tag the runner between bases" play: runners only take a base they beat the throw to, and at home the catcher needs `fielding.tagTime` extra to receive and tag.
- `planPlay` gives every fielder a job: `plan.paths[pos]` = his runs in order; `plan.fielderMoves` keeps one entry per run (with `role`: catch/field/cover/relay/backup/shade/watch). Backups, base coverage and pitcher/catcher roles are added in `addSupport` (movement only, never changes outcomes); `settleThrows` points each throw at where its receiver really is; `fielderFreeTime(plan, pos)` says when he may jog home.
- A dive (`planDiveRun`) only happens when the ball is just beyond running reach (`need > avail` but within `diveExtra`) AND no fielder could simply run to it within `fielding.dive.preferRun` seconds. He sprints straight at the ball (one committed direction), launches `dive.airTime` before the glove meets it, lands, slides, lies there, gets up. A fielder who dove throws later (`dive.throwExtra`). Plan events `dive` (launch), `diveLand`, and `catch`/`field` with `dive:true` drive the highlight (slow motion, dust, "DIVING CATCH!").
- The wall: `physics/field.js` has the ballpark outline (outfield wall + foul-territory walls + backstop): `isInsideField`, `clampToField(x, z, margin)`, `distanceToWall`, `wallClearance`. Every run target is pulled back inside by `fielding.wallMargin` (`addMove`); `planRun`/`planDiveRun` take `limitS` (how far he may travel before the wall) and brake harder - or start slowing earlier - so he stops in front of it (`wallBrake`); `sampleRun` also clamps to `limitS`. Home-run watchers stand a few feet in front of the wall. Anything that moves a person by other means (the jog-home `Mover`) has a `bound`. In the renderer a fielder whose play has ended finishes his planned run before the jog takes over (`st.tail`) - handing him over at full speed used to carry him through the wall.
- **Catching a fly ball** (`findAirCatch`, searched every 1/240 s so a short chance is never stepped over): the first moment a fielder CAN get under the ball is often when it is 8-9 ft up, out of his glove's reach - so a fielder who is there in time waits for it to come down to `fielding.catchHeight` (chest/head) and takes it there; if he cannot wait (it is about to hit the wall, or he is only just there) he takes it at the lowest height he still can. Above `standReach` he jumps: `plan.leap = { height }` (y - standReach, at most `reachHeight - standReach`), drawn by `leapHeight` in actors.js (root lifted by a parabola that peaks at `catchT`; the glove target follows the ball). The ball settles into the glove over the last `CATCH_SETTLE` (0.09 s) before a catch so a glove that is a little short never makes the ball snap. Do not go back to "catch at the first reachable moment" - that put every catch 4 ft above the glove.
- Renderer rules: facing only re-aims with a reason and turns at `fielding.turnRate`; every pose change cross-fades (`crossfadePose`); never use the ball's position as a facing target once it is in his glove.
- QA: `engine.contactOverride = () => ({exitVelocity, launchAngle, sprayAngle, backspin, hook})` forces an exact batted ball; `person.animState` names the current pose. `tests/fielderMotion.test.js` covers the run profile, mover, intercept prediction and dives.

### Base runners (game/runnerMotion.js)
- ONE model for the planner and the picture: `runnerProfile(from, to, kind)` = a route (straight baselines joined by a wide circular arc at every base he keeps running through: he drifts out, touches the bag at the middle of the arc, drifts back) plus a speed profile (he gets up to speed from a standstill, `accelTime`; on a curve he can only go `sqrt(latAccel / curvature)`, so he slows into a corner and speeds up out of it; he brakes at `brake` to stop on the last bag). `runnerArrival` / `runnerFinish` give the planner every arrival time (all the old `startDelay + n * per` formulas are gone); `runnerState(move, t)` is what the renderer draws (position, heading, speed, acceleration, sideways acceleration). The numbers in `config.runner` were calibrated so arrival times match the old constant-speed model within ~0.1 s (`tests/runnerMotion.test.js` guards it, and the simulator's win%/AVG/extra-base counts are unchanged) - if you change them, re-run `node scripts/sim.mjs 120 30 pro` and compare.
- A batter who is out at first runs THROUGH the bag (`kind 'through'`), started a touch later so he touches it exactly when the planner assumed. Home-run moves carry `trot: true`. A runner who stays put waits at his lead-off spot (`leadSpot`, also where he is drawn before the pitch).
- Renderer: `runnerPoseFrame` (waiting -> lead pose, running -> `runPose` with lean/bob/arm drive from his acceleration and turning, braking, slide when `wantsSlide` (a close play: an `out`/`safe` event at that base), sit, get up). `runPose(P, phase, speed, look, {accel, side})`; `slidePose`, `slideGetUp` in poses.js. The batter's start-in-the-box offset is added to the route and faded out (blending positions used to make him look 50% faster than his legs).

### Presentation
- **Pitch visibility:** the pitched ball is drawn at `pitch.ballScale` and never smaller on screen than hypot(real size, max(`pitch.minScreenPx`, screen height x `minScreenFrac`)) (`ball.js`, set per frame from `Actors.viewH`), so it is findable on a phone and still grows on its way in. Picture only.
- **Pitch guide** (`game/pitchGuide.js` pure + `render/pitchGuide.js`): a soft circle over the strike zone that guesses where the pitch will cross the plate. It fades in part-way through the flight (`difficulty.<level>.guide.fadeIn`, fractions of the flight), the guess starts on the no-break line (gravity only) and slides to the real spot between `reveal[0]` and `reveal[1]` (so curveballs/sliders show their end point late), it is off by a fixed per-pitch offset (`error`, so it never jitters) and the circle is bigger the less sure it is. Setting `pitchGuide` (pause menu + Play screen, default on; `?guide=0` for QA). Never shown in the Derby. Colour is neutral on purpose (never green/red).
- **Landing ring** (`game/landing.js` pure + `render/landingRing.js`): for a ball hit in the air (apex >= `landing.minApex`, not a home run, not a ball that hits the wall/stands before the grass) a soft ring sits on `sim.firstBounce` (exact), appears `landing.delay` after contact, fades in, shrinks from `radiusStart` to `radiusEnd` so it is smallest the moment the ball would land, and is hidden at the landing or, if a fielder catches it first, at `plan.catchT` (it is still sized by the landing time). The game camera looks along the grass at 2-8 degrees, so the renderer tilts the ring toward the camera (`viewTilt`, centred on the spot, no depth test) and never lets it get smaller than `minScreen` x its distance. Setting `landingRing` (pause menu + Play screen, default on; `?ring=0` for QA). `tests/landing.test.js`.
- `render/scene.js` renderer + adaptive resolution (`quality.*`); `environment.js` sky/sun/fog/day-dusk-night presets + clouds; `stadium.js` (+ `perimeter.js`, `crowd.js`, `scoreboard.js`, `textures.js`) the ballpark; `rig.js` person model + two-bone IK (parts merged into few meshes); `poses.js` procedural animation; `actors.js` drives every person and the ball from engine state; `cameraRig.js` broadcast camera (batter view -> follow -> snap back, shake); `ball.js` ball + trail; `effects.js` particles/fireworks.
- `audio/audio.js` - Web Audio synthesis (bat crack scaled by contact quality, glove pop, crowd, cheers, organ riff) and the umpire entry point. The AudioContext is created only after the first user gesture (`unlock()` -> `build(ctx)`, which an OfflineAudioContext can also use). **Channels:** `sfx` (effects; its reverb send `sfxVerb` follows it), `crowd` (ambience, pre-rendered applause buffer, organ), and the umpire (scaled per call by `levels.umpire`, routed straight to `master`); all go through `master` (volume) and a limiter. `setLevel('sfx'|'umpire'|'crowd', 0..1)`, `setVolume`. `setHidden(true)` suspends the context (tab hidden / page hidden). iPhones: `navigator.audioSession.type = 'playback'` so the silent switch does not mute the game.
- `ui/ui.js` + `style.css` - all menus/HUD. `app.js` - input, time control (hit-stop, slow-mo, fast-forward), engine->effects/audio/UI hooks.

### The players (rig.js)
- Same skeleton, IK and poses as always; only the shapes changed. Torso = a V-tapered lathe carrying the jersey texture (front at u = 0.25); short jersey sleeves over the team's undershirt colour (`uniform.sleeve`) or bare arms; side-striped pants, banded stirrup socks, molded cleats; a real glove (pocket, finger stall, thumb, laced webbing) and a bigger catcher's mitt; batting gloves, wristbands and elbow guard on batters; face with eyes/brows/nose/jaw, hair colour from skin tone + number, paneled cap with button and badge.
- Parts are merged into few meshes with vertex colours; `ao` on a part bakes a little ambient occlusion at its ends. `detail` (0..1) lowers polygon counts: fielders/coaches 0.62, everybody x0.75 on phones (`Actors.detailScale`). Keep full detail for batter/catcher/pitcher/umpire - they fill the screen.
- Caution: never make one part's surface coincide with another's (z-fighting shows as dotted rings) - make the outer part a touch wider.

### The umpire's sounds (audio/)
**How the owner's own recordings work (the easy path):**
- Files live in `public/sounds/umpire/` and are named after the call: `strike` (also the swinging strike), `ball` (also ball four), `strike3`, `foul`, `out`, `safe`, plus optional `ball4`. Extra takes add `_b`, `_c`... (`strike_b.mp3`); one is picked at random per call. `.mp3`, `.wav` and `.ogg` work; capitals are fine. `public/sounds/umpire/README.txt` explains it to the owner. **The folder currently holds only that README - the owner has not supplied any recordings yet**, so every call uses the built-in voice.
- The BUILD lists the folder (`scripts/umpireFiles.mjs` -> `define: __UMPIRE_FILES__` in `vite.config.js`), so the game only fetches files that exist - never probe for missing files (404s fill the console and smoke scenario 8 forbids failed downloads). The list is made when `vite` starts: after adding files, restart `npm run dev` (or push, so Vercel rebuilds). Files are loaded once after the first user gesture (`AudioEngine.unlock`), URLs built from `import.meta.env.BASE_URL`. `audio/umpireNames.js` maps file names to calls, `audio/umpireFiles.js` loads and picks takes.
- A call with a recording plays it (`playFile`: light stadium reverb + echo, `audio.umpire.files` = `level`, `reverb`, `echo`); calls without one use the built-in voice, so recordings can be added one call at a time. Mute and `umpireMode` ('synth' | 'speech' | 'off') are respected; `callUmpire` swallows any audio error.
- **The owner's tool**: `npm run umpire -- <call> <file or link> [--take b]` (`scripts/addumpire.mjs` + `scripts/umpireAudio.mjs`): downloads a link (curl; a web page instead of a sound file gives a clear message), trims silence off both ends (`silenceremove` + `areverse` trick), levels it (two-pass `loudnorm` to -16 LUFS, or a peak set to -1.5 dB for clips shorter than 0.6 s), writes a mono 44.1 kHz mp3 to `public/sounds/umpire/<call>[_take].mp3` and removes other-format copies of the same call/take. Needs ffmpeg (the script prints how to install it; it is installed in this sandbox at `/usr/bin/ffmpeg`). `--list` shows what is set up. Tests: `tests/umpireTool.test.js` (ffmpeg parts skip themselves when ffmpeg is missing), `tests/umpireFiles.test.js`.
- **When the owner gives a link or file**: run the tool for the right call, check with `--list`, run `npm test` and a build, commit and push (pushing to `main` makes Vercel rebuild). If the link cannot be downloaded (network policy), tell the owner to put the file in `public/sounds/umpire/` with the exact name.

**The built-in voice and the browser voices (when there is no recording):**
- Order used by `AudioEngine.callUmpire`, the only entry point: (1) recording, (2) built-in voice, (3) browser voice when the Voice setting is 'speech'.
- **Built-in voice.** `planCall(kind, voice, rng)` (pure, unit tested) lays a call out as a timeline of sounds (hiss, pop, voiced vowel with resonances + pitch contour). `renderCall(plan, rate)` (`audio/voiceRender.js`, pure JS, runs in Node) turns that into samples: a glottal pulse train (jitter, shimmer, creaky cycles) through a cascade of formant resonators that glide between sounds (each hiss/pop starts from its place in the mouth, so the transition into the vowel says which consonant it was), noise for hisses/bursts/breath. `speak()` (`umpireVoice.js`) plays the buffer through presence EQ -> compressor -> `placeVoice` (pan, reverb send, two slap-back echo taps; echoes are plain delay taps, never a feedback loop). Tunables: `audio.umpire` (`grit`, `squeeze`, `presenceDb`, `reverb`, `echo`, `level`, `pitchHz`, `rasp`). Do not raise `grit`/`rasp` far: distortion smears the words.
- **Browser voices** (`speechPlan`, `pickBestVoice`, `speakWithBrowserVoice`): phrases spoken low and slow with the best local male US voice the device has; the browser will not let a page process its voice (no echo/compression).
- Kinds: strike, strikeSwing, strike3, strike3Swing, ball, ball4, foul, safe, out. The app decides which (`App.onPitchCall`, `umpireCall`): strike three and ball four come from the engine's `pitchCall` payload (`result`); fouls from the 'landed' play event; outs from 'outCall'; close plays get a planner event `safe` (`addCalls`, `fielding.closePlay`). Derby has no calls. Gestures (`umpirePose(kind)`) always play, even with the voice off; base calls are voice only (panned), plate calls also gesture.
- Every game has one umpire character (`AudioEngine.setUmpire(seed)`): pitch/roughness/tempo; each call varies a little around it.
- QA without ears: `node scripts/umpirewav.mjs` writes every call as a .wav. `tests/voiceRender.test.js` checks pitch, vowel resonances, that consonants are quieter than vowels and that the loudest moment of "strike" is the "-eye". The most useful check used to tune the words was a speech recognizer (pocketsphinx, a stand-in for "does it sound like the word"): with a grammar of the calls, "strike" went from 0/10 understood to 9/10 once the hiss was made quieter than the vowel and the "Steee-" was dropped. Trust measurements over guesses: an unbalanced hiss made "strike" unintelligible.

### Menus and HUD (ui/ui.js + style.css)
- `style.css` starts with design tokens (color, spacing `--sp-*`, corners `--r-*`, motion `--ease/--dur`). Build every new control from `.btn` (`.ghost`, `.small`, `.wide`), `.iconbtn`, `.seg` (pick one), `.switch` (on/off), `.setrow`, `.card`, `.chip`, `.panel`; the pause menu's settings sit in a two-column `.setgrid` so they fit phone landscape. Hover effects live inside `@media (hover: hover)` so phones never get stuck hover states. Icons are inline SVG from the `ICONS` map in `ui.js` (`icon('name')`).
- Text rule: labels only. No paragraph under a header, no explanatory sentences in menus or overlays; if something needs a sentence it does not belong on screen.
- Screens: `fresh(name)` gives an empty screen; if it is already showing (a setting was tapped) it is rebuilt without replaying the entrance animation (`.still`). Anything that must animate in gets `class="rise"` and is a direct child of the screen. Settings inside screens go through `settingClick` (works for `.seg` and `.switch`).
- Saved settings (defaults in `game/progression.js`, all in localStorage): difficulty, time of day (`tod`), strike zone, pitch guide, landing ring, umpire voice (`umpire`: synth / speech / off), batting hand, sound, `volume` (master), `sfxVolume`, `umpireVolume`, `crowdVolume`, `shake`, `flashes`, `inputDelayMs` (0-150 ms taken off every press; `Engine({inputDelayMs})`), plus flags for the how-to screen and the aim hint. A first visit with prefers-reduced-motion starts with shake and flashes off.
- **Screens:** title, modes (Play: mode cards + Level / Time / Bats), how-to, locker, career, **settings** (everything, sliders apply live and save on release, releasing plays a sample), **credits** (three.js MIT notice), pause (resume, zone / guide / ring / sound switches, Settings, Help, Restart, Quit), results. `App.openMenu(name)` pushes where you came from onto `App.nav`; Back and Esc pop it (`App.escape()`). Buttons that lose something carry `data-confirm` and go through `UI.confirmed()` (first tap arms "Sure?", second does it).
- **Keyboard:** outside gameplay a focused control gets Enter/Space/arrows natively (the swing handler only takes them when no menu is up); starting a game or resuming blurs focus so Space always swings. Esc backs out of every menu / pauses / resumes.
- HUD layout (keeps overlays from ever colliding): top-left pause/mute; top-centre pitch pill, then the exit-speed readout / hint; top-right practice drawer (folded to an icon button up to 900 px wide; in phone portrait it sits below the readouts); bottom-left score bug (Quick) or Derby scoreboard; bottom-centre timing meter (raised above the bug row); bottom-right aim gauge (desktop) or aim buttons at the sides (touch). Which panel shows is decided by `.hud[data-mode]` in CSS, never by inline `display`. Call banners are a compact plate; only home runs get the big celebration. Check any HUD change with `node scripts/hudqa.mjs` (default sizes 568x320, 844x390, 1280x720, 390x844; also try tablets 768x1024, 1024x600).

### Startup, loading screen and the boot guard (do not bypass)
- `index.html` has an **inline classic script** (`window.__sandlotBoot`) that owns the splash (logo + progress bar `#boot-bar`/`#boot-fill` + `#boot-msg`) and the `#boot-error` screen. `progress(f, label)` moves the bar (never backwards); before the first report it creeps toward 35% while the game downloads. `App.init` reports 0.42 ballpark, 0.66 players, 0.84 lights (shaders precompiled: `compileAsync` when `KHR_parallel_shader_compile` exists, else `compile` - calling compileAsync without it logs a warning, which the smoke test treats as a failure), 0.96, then `done()` after the first frame. It works even when the game's own files never load. `done()` hides the splash; `fail(kind, err)` shows a readable error (kinds: `load`, `start`, `frame`, `timeout`). State is mirrored in `<html data-boot="loading|ready|failed:<kind>">`.
- It catches: the module script failing to load (capture-phase `error` on `<script>`), uncaught exceptions / rejected promises while starting, and a 45 s timeout (soft "still loading" note at 12 s).
- `main.js` builds the `App` inside try/catch and starts on a timer as well as on an animation frame (frames never fire in hidden tabs). `App.loop` requests the next frame first, guards each frame with try/catch, and calls `__sandlotBoot.done()` only after the first frame draws; repeated frame errors stop the loop and call `fail('frame')`.
- Never add startup work that can throw or wait without going through this path, and never remove the splash anywhere else.

## Conventions
- Put every tunable number in `src/config.js` with a plain-English comment. No magic numbers in logic.
- Logic modules must not import three.js or touch the DOM (so Vitest and `scripts/sim.mjs` can run them in Node).
- Timing must never depend on frame rate: use engine time and `swingPressed(sinceUpdate)`; physics is precomputed at fixed steps.
- Renderers read engine state; they never change game outcomes.
- After changing physics/fielding/contact numbers: run `npm test` and `node scripts/sim.mjs 100 30 pro` and check win% / AVG still look sane (see the baselines above).
- QA hooks: `?mode=quick|derby|practice&bot=1&sd=25&seed=7&tod=night` starts a game immediately (bot plays); `?guide=0` / `?ring=0` hide the pitch guide / landing ring; `window.__app.tick(dt, render)` steps the simulation without waiting for real time (used by headless-browser QA).
- Commit messages: clear, one milestone/topic each. Text the owner sees (menus, overlays) is labels only.

## Known issues and unfinished ideas
Nothing here breaks the game; these are the honest rough edges and the things not done.
- **Vercel's production branch is unverified from here.** GitHub's default branch is an old `claude/...` branch. If the Vercel site does not show a change that GitHub Pages shows, the owner should set Vercel's Production Branch to `main` (and ideally GitHub's default branch to `main`).
- **Vercel is not gated by tests.** Only the GitHub workflow runs tests and the smoke test. Run the checks yourself before pushing to `main`.
- **No umpire recordings yet.** The folder holds only its README, so every call uses the synthesized voice, tuned by measurement, never by the owner's ear.
- **Feel of the newest features is untested by the owner** (pitch guide, landing ring, wall leaps, the new mix levels, the pitch's minimum size, the loading screen). All are plain numbers in `config.js`.
- **Fielding is fully deterministic and never misplays.** There is no error model (the unused `fielding.errorRate` knob was removed). If misplays are wanted they have to be built in `planPlay`, seeded so plays stay repeatable.
- **Bot stats look generous** (.542, 85% wins on Pro): the bot swings at 85% of strikes and 6% of balls with ~30 ms timing error; people are far below that. Do not "fix" this by making fielders stronger without also checking `groundcheck.mjs` and `wallcatch.mjs`.
- **Fonts:** the logo is shapes (same everywhere), but headings such as "YOU WIN" and "HOME RUN!" use the system's heavy italic (`--font-display`: Arial Black / Impact where present), so they look slightly different on Android. Bundling a font would need a font file in the repo.
- **Real-device performance was never measured** (this sandbox renders in software). Per-frame game logic is under 1 ms; startup was 2-4 s in software rendering.
- **By design, the player only bats.** No steals, pickoffs or rundowns.
- **Nothing else is queued.** Further work comes from the owner's playtest notes. Do not invent features.

## Working in this sandbox (things that cost time before)
- **Never use `pkill -f` / `pgrep -f` with a pattern that also appears in the same shell command** - it matches the shell itself and kills it (this happened three times, exit 144). To stop a dev server: find it with `pgrep -x node`, confirm it is the right one from `/proc/<pid>/cmdline`, then `kill <pid>`.
- There is no `gh` CLI: use the GitHub MCP tools (`mcp__github__*`) for PRs, Actions runs and checks. Git push works from the shell.
- Headless Chromium is at `/opt/pw-browsers/chromium` (use `playwright-core` with `executablePath`; never run `playwright install`). The `*qa.mjs` scripts and smoke run headless. `page.evaluate` takes ONE argument (wrap several in an object). Do not put an `expect()` inside a per-sample loop in tests - collect problems and assert once (thousands of `expect` calls time tests out). Long simulation tests need an explicit timeout.
- `ffmpeg` is NOT installed in this sandbox (the three ffmpeg tests skip). Live sites (vercel.app, github.io) are blocked by the network policy.
- The smoke test builds several variants into temp folders; a scenario's folder name must not clash with another scenario's (a clash once wiped the pretend recordings folder).
- Outbound network is limited by the sandbox proxy: a recording link may not download (tell the owner to drop the file in `public/sounds/umpire/`).
