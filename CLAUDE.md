# CLAUDE.md - Sandlot

Browser baseball batting game ("spiritual successor to the old doodle baseball game", far more polished). **Vite + vanilla JS + three.js.** Everything (textures, sound effects, people, crowd) is generated in code - the only asset files are the umpire's recordings (`public/sounds/umpire/`). The owner does not code: they judge by playing, so keep commands and explanations plain-English and never leave TODOs.

Modes: **League** (called Season in the code and the save: pick one of the 30 big-league clubs with their REAL names, colours and best hitters - personal use only, said in Credits - and play your 4 division rivals plus 4 teams of a neighbouring division, 6-inning games, standings, playoffs and a World Series, coins, a shop, a rated roster; you always bat in the bottom half), **Quick Game** (3 innings vs the computer, extra-innings runner on 2nd, walk-offs), **Home Run Derby** (10 outs, batting-practice pitches), **Practice** (pick the pitch; runners stay on base and runs are counted, no outs). Three levels: Rookie, Pro, All-Star. The player only bats; the computer's half-innings are simulated instantly.

## Commands
- `npm run dev` - dev server (http://localhost:5173)
- `npm test` - Vitest (`tests/*.test.js`, pure logic, no browser)
- `npm run build` - production build to `dist/`. The base path comes from `scripts/resolveBase.mjs` (see Deployment). `vercel.json` holds the Vercel settings.
- `npm run smoke` - (after a build) serves `dist/` under a `/<repo>/` sub-path and drives headless Chrome: must reach the title screen and survive a real click-through (Settings with a volume slider, Credits, Esc back twice, Play, how-to, a setting, Quick Game, pause, the zone / pitch-guide / ring switches, one tap on Quit only arms it, resume). Console warnings count as failures. Eight scenarios (the click-through uses the `.tile[data-mode=quick]` tile): (1) built game reaches the title, (2) menus with real clicks, (3) Vercel-style build served at `/`, (4) default build (`./` base) served from another folder, (5) a build made for the wrong base served at the root of a non-GitHub host -> readable error that does not mention GitHub, (6) WebGL blocked -> the "couldn't start 3D graphics" screen, (7) the raw un-built source -> the "game files didn't load" screen, (8) a pretend recordings folder (`SANDLOT_UMPIRE_DIR`) -> files found by the build, downloaded after the first click, played, a call without a file is silent, and nothing 404s. `CHROME_PATH=/path/to/chrome` picks the browser (in this sandbox `/opt/pw-browsers/chromium`; CI uses the runner's Chrome).
- `npm run sim` / `node scripts/sim.mjs [games] [timingSdMs] [difficulty]` - headless bot playtest with stats (win %, AVG, HR, outcome table by contact grade). Use it after changing physics/fielding/contact numbers.
- `node scripts/pitchmix.mjs [pitches]` - where the computer pitcher throws, per difficulty.
- `node scripts/hrrate.mjs [swings] [derby|quick]` - home run % for perfect and good swings by level. Derby targets: perfect ~70-85%, good ~25-40%; `tests/hrrate.test.js` guards the bands. Derby-only batting help lives in `modes.derby` and reaches `computeContact` through `derbyBatting(cfg)`.
- `node scripts/feel.mjs [swings] [new|average|good] [quick|derby]` - how batting feels to a PERSON: a simulated player follows the pitch guide with a human reaction delay (`react`), hand shake and timing spread (`PLAYERS`) and swings at hittable pitches through the real swing, collision, flight and fielders. Prints contact % / miss % (and why) and fair / hit / HR per swing per level. `tests/feel.test.js` guards it. Round-five numbers (miss %, new / average / good): Rookie 8 / 3 / 0, Pro 27 / 12 / 3, All-Star 60 / 33 / 13; HR per swing on Pro 2 / 5 / 10%.
- `node scripts/guidecheck.mjs [pitches]` - how readable the pitch guide is per level, at the moment the batter must DECIDE (`timing.decideTime` before the swing must start). `node scripts/guideqa.mjs <dev-server url>` checks it in the real game.
- `node scripts/landingqa.mjs <dev-server url>` - the landing ring in the real game (spot vs where the ball lands, shrink, hide, switch).
- `node scripts/groundcheck.mjs [plays]` - thousands of ground balls through the planner and the referee (`src/game/playAudit.js`): every out must have a fielder ON the bag WITH the ball before the runner. Must say "no problems". `node scripts/groundqa.mjs <dev-server url>` measures the picture at the moment of the out.
- `node scripts/wallcatch.mjs [balls] [bandFeet]` - catch rate on catchable fly balls near the wall (must be 100%, `tests/wallcatch.test.js`). `node scripts/wallqa.mjs <dev-server url>` checks the picture.
- `node scripts/wallcheck.mjs [plays]` - any fielder outside the ballpark (`tests/wall.test.js`).
- `node scripts/tune.mjs [samples] [sdMs] [difficulty]` - hit/out/HR rate by batted-ball type.
- `node scripts/realism.mjs [balls] [seed]` - thousands of batted balls in every base / out situation through the real planner, next to rough big-league numbers (who fields, who covers second, double plays, the runner on third, sac flies by depth, extra bases on hits) plus the referee's verdict. ## Architecture (three layers)
1. **Logic (no graphics, unit tested)** - `src/game`, `src/physics`
2. **Presentation** - `src/render` (three.js), `src/audio`, `src/ui` (DOM)
3. **`src/app.js`** wires them together (input, time control, engine -> effects/audio/UI hooks, menu navigation, Season games). `src/main.js` boots it: `new App(...)` only stores the canvas, `await app.init(report)` builds everything in stages and reports progress to the splash. `src/config.js` holds ALL tunable numbers. `src/util/` = `math.js`, `rng.js` (seedable).

Module map:
- `src/physics/`: `field.js`, `pitch.js`, `ballistics.js` (+ the backstop net), `bat.js`
- `src/game/`: `engine`, `timing`, `contact`, `fielding`, `fielderMotion`, `playAudit`, `runnerMotion`, `rules`, `pitcherAI`, `aiHalf`, `pitchGuide`, `landing`, `progression`, `teams`, `mlb`, `season`, `bot`
- `src/render/`: `scene`, `environment`, `stadium` (+ `perimeter`, `crowd`, `scoreboard`, `textures`, `parkLook` - each park's decks, roof, backdrop and landmarks from `config.parks.looks`), `rig`, `poses`, `actors`, `cameraRig`, `ball`, `effects`, `pitchGuide`, `landingRing`, `batAim`
- `src/audio/`: `audio` (engine + umpire), `umpireFiles`, `umpireNames`
- `src/ui/ui.js` + `src/style.css` + `src/ui/logo.js`
- `scripts/` (Node tools and QA), `tests/` (31 files), `public/` (icons, share picture, manifest, `sounds/umpire/`)

### Coordinates (used by every module)
Feet. Origin = back tip of home plate. `+x` = right-field side (screen-right from behind the plate), `-z` = toward the pitcher / center field, `+y` up. Spray angle 0 = center, negative = left field. The camera sits behind the plate at `+z`. Person-local axes: `+z` = the way they face, `+x` = their LEFT hand. Left-handed batters and pitchers are the same figure mirrored (`root.scale.x = -1`); their jersey artwork is pre-flipped about the FRONT of the shirt (u = 0.25).

### Logic (`src/game`, `src/physics`)
- `physics/field.js` - bases, fence curve, fair/foul test, grandstand profile, the ballpark outline for the wall code, the dugouts. **Ballparks**: `setPark(id)` (a key of `config.parks.list`) rewrites `CONFIG.field.fencePoints` / `fenceHeight` / `physics.dragK` and rebuilds the outline; `fenceHeightAt(spray)` (walls vary: Fenway's Monster), `currentPark()`. Sandlot Park is the default and what every test assumes (`tests/parks.test.js` switches and resets). The app calls `S.setPark` (render/scene.js: throws the stadium away - `disposeTree` - and builds it again) before every game: League = your club's park, else `settings.park` (Play screen **Park**), a resumed Quick Game keeps its park.
- `physics/pitch.js` - `buildPitch`: a constant-acceleration path solved to hit a chosen spot at the timing plane. `pace` (`difficulty.<level>.pitchPace`): the ball takes that many times longer to arrive than a real pitch at the speed shown (round five: easier to read; the speed shown, the timing windows and the exit velocity are unchanged). `zoneRatio` = how far a spot is from the middle of the zone (1.0 = the edge).
- `physics/ballistics.js` - `simulateBattedBall`: fixed-step (1/240 s) flight with gravity, drag, lift, hook, bounces, rolling, wall, stands. Also `judgeFairFoul`.
- `game/timing.js` - timing windows and `resolveSwingTimes`. **Error = bat time - ball time (ms)**.
- `physics/bat.js` - the bat-ball collision: `collide` / `hitBall` (an impulse model: restitution, friction capped at mu x the normal impulse, spin from the off-centre impulse; `bat.*` in config) and `describe` (exit velocity, launch, spray, backspin, sidespin). Offset `u` = how far the ball's centre is above the bat's (share of ball + barrel radius): u > 0 = bat under the ball (fly ball, backspin), 0 = line drive, < 0 = grounder / topspin.
- `game/contact.js` - `contactPoint(flight, tHit, tBarrel)` (the ball where the bat meets it, on the swing plane; the ball's velocity is scaled back up by `flight.pace` so the bat feels the pitch's real speed), `contactWindow(level)` (how far from the sweet spot the bat still TOUCHES the ball: up / tip / handle, plus `sweet` = `difficulty.<level>.sweetSpot`, the smaller part that decides how it comes off - beyond it inside the window the bat only gets a piece of it; `scaleWindow` for the Contact rating and `modes.derby.windowGrow`), `batOffset`, `computeSwing(i)` (aim + ball + timing -> the collision; misses report `under` / `over` / `end` / `hands` / `timing`; timing sets bat speed and the barrel's heading: early pulls, late goes the other way, `pullBias`), `derbyBatting()` (`evBonus`), `computeBunt` (the bunt also reads where the bat is: on top of the ball = down, under it = popped up). The engine's `batAim` ({x, y} on the plane over the plate, `setBatAim`, clamped to `swing.reach`) is locked at the press.
- `game/fielding.js` - `planPlay`: given the ball flight + runners, decides catch / groundout / hit / extra bases / double play / sac fly / error and returns a **plan** (fielder paths, throws, carries, loose-ball segments, runner moves, events, `endTime`). Deterministic. Inputs beyond the ball: `errorRoll` / `errorScale` (errors), `running` (runners going with the pitch), `speeds` (each runner's speed factor). `planSteal` plans a stolen-base attempt (no ball in play). Module state (`RUN`, `SPD`) is set only while those run.
- `game/rules.js` - counts, outs, walks, force advancement, `applyPlay` (results incl. `sacBunt`, `error` - an at-bat, not a hit, charged to the fielding team in `g.errors`), `applySteal`, innings, extra innings, walk-offs, line score.
- `game/pitcherAI.js` - what to throw and where ('heart' / 'edge' / 'chase' / 'waste' odds per level, shifted by the count). `game/aiHalf.js` - the computer's half-inning from odds (`difficulty.<level>.ai`, incl. `error` = safe on your fielders' error).
- `game/engine.js` - **the orchestrator**: phases `ready -> windup -> pitch -> (play) -> result -> ...`. Ready button: `waitForBatter` holds the first pitch to each new batter until `batterReady()` (the app passes it for Quick/Season games without the bot; the bot presses it itself). Bunting: `setBunt(on)`. Stealing: `setSteal(on)` / `stealBases()` / `canSteal`; `beginSteal()` at the windup rolls the jump and the catcher's exchange and plans the steal at once (`this.steal.plan`, drawn during the pitch). No contact -> `startStealPlay` / `finishSteal` (a play with `plan.steal`, a stub flight `NO_FLIGHT`); contact -> `planPlay({ running })` (hit-and-run). **You bat last**: `playerSide` is 'bottom' (default; tests that start a game and act pin `playerSide: 'top'`), the computer's half is `runAiHalf()` and `start()` plays it first. **Saving**: `checkpoint()` (emitted before every pitch) / `saveState()` / `resume(st)`; the rng is re-seeded from `seed ^ imul(rngN, 0x9e3779b1)` at each pitch, so a resumed League game throws exactly the same pitch. Steal timing: a runner breaks `difficulty.<level>.stealBreak` seconds before the pitch is released (not from the start of the windup, so a longer windup does not make steals easier). Season options: `innings`, `lineup` (rated players), `opponent`, `playerTeam` (name, abbr, colour, uniform), `oppLineup`, and a derived `cfg` (constructor 2nd argument). `ratingEffects(batter)` -> Contact widens `windowScale`, Power `evBonus`; `runnerSpeeds()` -> Speed. Practice keeps a game state `pgame` (runners, runs; outs reset every play); `diamond` = `game || pgame`. QA hooks: `pitchOverride`, `contactOverride`, `errorRollOverride` (0 = always an error).
- `game/progression.js` - localStorage (try/catch, in-memory fallback; key `sandlot.save.v1`), career stats, high scores, unlocks, and `data.season` (the whole Season as JSON; `resetStats()` keeps it). Season games count toward career games/wins but not Quick Game bests.
- `game/mlb.js` - the League's data (pure): `MLB_TEAMS` (30 clubs: real city, colours and division; changed nickname; `tier` 1-5; 3-5 stars each as `[name, pos, contact, power, speed, bats]`), `uniformFor(team, 'home'|'away')` (home = team-colour jersey, away = road grey with the team colours, so two teams never clash), `leagueFor(teamId, seed)` (your team + your division + 4 of the 5 teams of a neighbouring division), `starsOf`, `allStars`, `teamLineup(team, seed)` (the opponent's nine), `shortName`. The Quick Game picks a random club as the opponent too.
- `game/season.js` - League (called Season in the code and the save; pure): `newSeason(prev, { level, length, team })` (9 teams from `leagueFor`, each with a strength from `season.tierRating[tier]` + `boost`; your 12-man roster = your club's stars at their positions + role players rated `roleMean(tier)` + a bench; the shop: journeymen and, `shop.starChance`, a star from another team), `makeSchedule` (circle-method round robin with a bye; your opponents weakest-first, off day mid-cycle; 1 or 2 cycles), `nextGame`, `standings`, `recordGame(s, { won, runsFor, runsAgainst, lines })` (standings, player season lines, coins, other games simulated with `simK`, off days, playoffs: 1v4 / 2v3 one-game semis then best-of-`finalGames` World Series), `isOver`, `finishSeason`, `finishOf`, `swapPlayers`, `buyPlayer` (full roster -> replaces a player, `refund`), `price`, `overall`, `gameConfig(level, rating)` (a strong team: faster fastball, fewer heart pitches, better command, more hits / fewer Ks when it bats, fewer errors, quicker catcher), `gameSetup` (also returns `playerTeam` with its home uniform and the opponent with its away uniform), `ratingEffects`. `s.inProgress` holds a half-played game. Next year: roster and coins carry over; `boost` grows by `yearStep` after a title (half after a playoff trip), capped at `yearCap`.
- `game/teams.js` - Sandlot's own team, the Locker's uniforms and bats, the names for generated Quick Game batters (`SKINS` is shared). `game/bot.js` - test bot.

### Fielding, errors and outs
- `game/fielderMotion.js` is the ONE movement model (`covered`/`timeToCover`, `planRun`, `planDiveRun`, `Mover`). What the planner promises is exactly what is drawn.
- **The third out ends the play** (`endInningStop`): runners still going ease up and stop; no `safe` call for a base never reached.
- **Covering a base** (`coverOptions`): an out at a base only exists if somebody is on the bag with the ball before the runner (throw timed to the cover man, or the fielder carries it). Options: `tag` (seconds to tag a runner who is not forced - steals use `steal.tagTime`; home always `fielding.tagTime`), `coverStart` (steals: the cover man broke when the runner went). Force plays, double plays, hit plays, steals and doubling a runner off all use it. `auditPlan` (tests/groundouts, tests/steal, tests/errors) checks every out, including on caught balls and runners going back (`retreatArrival`).
- **Errors** (`fielding.errors`, x `difficulty.<level>.errorScale`, x `hardFactor` on a smash / dive / leap): a bobbled grounder (`bobble`) or a dropped fly (`dropFly`). The ball pops loose (`plan.looses` segments, drawn by `actors.ballInPlay` kind 'loose'), the fielder chases it (`chaseLoose`), then `finishHit` gives the runners what the delay allows. `plan.result = 'error'`, `plan.error = { pos, kind, t }`, event `error`. Decided by one seeded roll per ball in play (none in the Derby, none without a roll). ~1 error per 100 balls in play.
- **Who makes the play** (round three): a first baseman who has the ball near his bag walks over and steps on it (`cover.firstSelfDistance`, `firstSelfBonus`); on a thin force play the sure out at first wins (`fielding.thinForce`, `thinForceGain`); both outfielders break for an outfield ball and only one makes the catch (`chaseShare`); outfielders react slower (`reaction.OF` .52) and fewer balls are caught.
- **Tags**: `coverOptions` marks an option `tagged` when the runner is not forced (steals, home, runners on the bases); `planOut` writes `tag: true` on the `out` event. The picture (`actors.computeFielderPose`) gives every receiver of a throw a catch pose and, on a tag event, sweeps the glove down onto the runner (`tagOut`).
- Dives, the wall, catching fly balls at chest height, leaps at the wall: unchanged from before (see `findAirCatch`, `planDiveRun`, `wallBrake`, `CATCH_SETTLE`). Do not go back to "catch at the first reachable moment".

### Base runners (game/runnerMotion.js)
- ONE model for the planner and the picture: `runnerProfile(from, to, kind, cfg, spd)` (route with rounded corners + speed profile; `spd` = the runner's speed factor), `runnerArrival` / `runnerFinish`, `runnerState(move, t)` (moves carry `tStart`, `spd`, `back`, `backAt`, `stopAt`). Leads: `runner.lead` 9 ft, `runner.leadSecond` 18 ft (these shorten every runner's trip; `tests/runnerMotion.test.js` allows for them).
- **Going back** (`retreatState`, `retreatArrival`): a runner who went with the pitch runs on until `backAt`, pulls up, turns and runs back to the bag he left (not his lead spot). Used on fouls (`steal.readFoul`), caught balls (line drive: when it is caught; fly: `steal.readFly`) and when he ends up holding. On a caught ball one going runner may be doubled off (`runnersGoBack`), through `coverOptions`.
- **Steals** (`config.steal`): jump `steal.jump` + `jumpSd` after the windup starts; catcher exchange `steal.transfer` x `difficulty.<level>.catcherArm` (+ `dirtExtra` for a pitch in the dirt); throw to the lead runner; out only if the ball is on the bag + tag before him; no throw when hopeless (`noThrow`). Measured success (steal of second): Rookie ~88%, Pro ~76%, All-Star ~58%; of third a little lower (`qa-output`-style measurement: steal attempts through the real engine with no swings).
- **Reading the play**: on a grounder runners go at once (`runner.read`); on a ball in the AIR (`fielding.airLegs`, fewer than two outs) every runner does exactly the same whether it will be caught or not until it is caught or comes down (`plan.airRes`): first / second go `runner.halfway` of the way (a `half` leg) and wait, third - and second on a ball coming down past `runner.tagDepth` - goes back to the bag to tag up (`tagBack`), on a line drive a step or two (`halfwayLine`); then they react in `downReact`. With two outs they run on contact. Slides come from `actors.wantsSlide` (any out or safe call at a base from second on).
- **Runner orders (round six, simplified in round nine)**: on their own runners only move when FORCED (`runner.freeAdvance` false: `finishHit` holds a free runner, `advanceOnGroundout` and the runner-on-third break in `tryInfieldOut` only move him when he is going with the pitch; true = the old rule, a free runner takes the next base when safe); the batter stops at first (on a ball an outfielder fields runners ROUND their base, `move.round`), and NEVER an extra base by themselves (`runner.autoExtra` false; with true: one more when safe by `runner.autoMargin`, `m.auto`). A runner you sent who would be tagged sees the throw (`runner.retreatRead` after it is let go) and turns back to the bag he left when it is free and he beats a throw there (`plan.retreated`). `i.orders` = [{ base, t, from, back }]: a plain order sends the runner heading for `base - 1` on to `base` (a runner ahead in the way goes too), `back` calls a runner you sent to `base` back to `base - 1` (not a forced runner, not with a runner behind him going there). The planner keeps a RECORD per runner { from, to, legs, sent, sentTo, recalled, forced, lockAt } (`fielding.makeRecords`, `applyOrder`, `recToMove`); legs change through `runnerMotion.extendLegs` / `backLegs` (leg kinds `run` / `round` / `half` / `resume` (from where he is, with `v0`) / `reverse` (brakes, turns, runs back to a bag) / a run `fromBag` with a rocking start `v0 = tagRoll` for a tag-up). `plan.send = { from: runner.sendFrom, by, decide, res, pre, post }` on EVERY ball in play (homers and fouls too): `sendOptions(plan, t)` gives the tappable bases ({ base, from, kind: 'send' | 'back' }) from `pre` (before `res`, identical for a catch and a drop) or `post`. Hits (`finishHit`): orders in the air, then each runner's base at `airRes`, then later orders, then the auto step; the throw goes for the lead SENT runner it can beat as things stood at `decide` (= `runner.sendLead` before the fielder is ready); `by` = `sendAfter` after he is ready; a runner sent after `decide` is chased by ONE `followUpThrow` from whoever has the ball. Caught balls (`caughtRunners`): at the catch everyone off his bag goes back (`backLegs`), a runner you sent before it can be doubled off (an appeal: no tag), the man on third (and second on a deep one) tags up by himself if it is safe, and after the catch you can send runners to tag up until `tagWindow` - one throw: doubled off, else at the lead tag-up runner (else a late throw home). Groundouts (`groundoutOrders`): sends until the last out + `sendAfter`, then one follow-up throw. Fouls: a sent runner goes and comes back. **Tag outs** (`tagRunner`): the out is made as he slides in (`arrive - runner.tagLead`), the man covering the bag stops ON it (`addMove` `stop`) and stays until the tag (`fielderFreeTime`), the runner walks off to the third-base dugout (`move.walkOff`, `runnerState` -> `walkOffState`), the play lasts `runner.outLinger` after it, `plan.outNote` = { base, from } and `plan.sentOut` feed the banner (*Out at 2nd*, *Runner out at home*, *Doubled off 1st*). Engine: `baseTargets()` / `tapBase(base)` (what the player and the bot use: `fielding.tapOptions` = the lit bases, a base only when nobody not out is heading for it, home always; re-plan, everything before the tap is identical); `runnerTargets()` / `runnerOrder(from, 'send' | 'back' | 'tag')` and `sendTargets` / `sendRunner(base)` still exist (tests) but nothing on screen uses them. HUD pad (`ui.setBasePad({ open, dots })`, dots carry `canBack`): the diamond only - `.bpbase` buttons (a big invisible tap target, `.open` = lit gold, drawn over the dots), coloured runner dots without labels (a ring on a runner you can call back), no text; size `--bp`. Keys 1 / 2 / 3 / 4 / H tap that base, Shift + them call back. The bot only taps after `res`, when a hypothetical re-plan says he makes it (`sendGamble` 1.5% per look = its misjudgements). Only Space fast-forwards a play.
- A batter who is out at first runs THROUGH the bag. Home-run moves trot (a runner already going is matched onto the trot). A runner who stays put waits at his lead spot until the ball is fielded, then goes back to his bag (`holdBackDelay` / `holdBackSpeed`, drawn by `actors.runnerUpdate`); after a play, runners walk (never glide) to their bag and only to their lead once the pitcher is set (`leadAfterSet`).

### Presentation
- **The ball you watch** (`render/ball.js`, `pitch.*` keys): the pitched ball has a dark rim (inverted hull), bolder seams, a soft ground shadow and a short streak (points) behind it - no halo. A ball in the seats bounces and stops there (`actors` HR seat bounce); the home run celebration plays once (`App.hrShown`); hit banners lead with the runs and put the hit in the small line.
- **Batting view (round four, lowered in round five)**: after Ready (`App.isBatting`) the camera eases into the catcher's view (`camera.catcher`: low behind the catcher, the zone mid-screen with the pitcher right behind it, so the pitch comes straight at you); the catcher and the umpire are hidden in that view and come back once the camera is `clearDist` away after a swing. The **see-through bat** (`render/batAim.js`, `batAim.*`) follows the cursor (a ray onto the plane over the plate), arrow keys, or a dragged finger (`touchGain`); its yellow ring is the sweet spot. On a swing it freezes where it was swung and fades (no other marks over the zone). While bunting (B) there is no bat cursor: he squares around at once and bunts by himself (`engine.autoBunt`, `bunt.auto*`). Touch: the round **Swing** button (`.swingbtn`), a tap while the pitch is in flight, or a second finger. The batter's stance follows the bat's height, and the swing (`actors.batterAtPlate` -> `batterPose` contact point) puts the real bat's sweet spot exactly where you aimed on a miss, and on a hit where the bat physically had to be (the ball's centre minus the contact offset u x (ball + barrel radius)) - measured 0.00 ft off at contact.
- **Pitch visibility:** the pitched ball is drawn at `pitch.ballScale` and never smaller on screen than `pitch.minScreenPx` / `minScreenFrac`. No glow/halo around the ball (removed on purpose).
- **Pitch guide** (`game/pitchGuide.js` + `render/pitchGuide.js`): fades in early enough to decide (`difficulty.<level>.guide.fadeIn` fractions of the flight), slides from the no-break line to the real spot between `reveal[0]` and `reveal[1]`, off by a fixed per-pitch `error`. Never shown before release. Rookie/Pro name the pitch type as it leaves the hand (`typeAtRelease`). Measured at the decision moment (`timing.decideTime` before the swing must start): right side of the zone Rookie 97% / Pro 87% / All-Star 71% (borderline 91 / 74 / 61). `tests/pitchGuide.test.js` guards it.
- **Landing ring** (`game/landing.js` + `render/landingRing.js`): lies FLAT on the grass (a plane with polygon offset, no tilt) exactly where the ball comes down (or at the catch / drop spot), shrinks from `radiusStart` to `radiusEnd`. The deep-ball camera rises to a "high home" view (`camera.highHome`) so the flat ring is readable.
- `render/scene.js` renderer + adaptive resolution; `environment.js` sky/sun/fog/day-dusk-night presets + clouds + **image-based sky light** (`bakeEnv`: a PMREM of the preset's sky/horizon/ground/sun per time of day, `envIntensity` per preset; the hemisphere light is lower to match). Night is deliberately dim (`sunIntensity` 1.85, exposure 0.92).
- `stadium.js` (+ `perimeter.js`, `crowd.js`, `scoreboard.js` with an E column, `textures.js`), `rig.js` person model + two-bone IK, `poses.js` procedural animation, `actors.js` drives everyone and the ball from engine state (steals are drawn from `E.steal` before there is a play; the covering infielder follows `E.steal.plan` during the pitch), `cameraRig.js`, `ball.js`, `effects.js`.

### The players (rig.js, poses.js)
- Rig: V-tapered jersey torso with a trapezius slope to each shoulder, short sleeves over undershirt or bare arms with biceps and forearm shape, tapered pant legs with knees, calves in stirrup socks, cleats, a real glove / catcher's mitt, hands with four curled fingers and a thumb (a batter's hands are closed fists in batting gloves: four finger rings that wrap right round the handle and a thumb across the front), face, cap/helmet. Parts are merged per limb (a bare hand is its own piece on the `wrist` group so it can turn); `scale` (height) scales the whole figure evenly and `build` only widens the pelvis, torso, yoke and shoulder spacing (a root stretched sideways used to shear every limb that turned, so wide players held the bat differently); `detail` lowers polygon counts for fielders/phones. Never let two parts' surfaces coincide (z-fighting).
- **Grip** (`Person.apply`, `GRIP` in rig.js): each fist closes ROUND the bat - the bottom hand `GRIP.bottom` (0.17 ft) up from the knob, the top hand touching it at `GRIP.top` (0.43; a pose can slide it up with `gripTop`, the bunt uses 1.05) - with the handle through `GRIP.point` inside the fist; the wrist turns so the bat lies across the fingers (index finger toward the barrel, back of the hand toward the elbow), solved in two passes (hand pointing back at the shoulder, then at where the elbow really went). Putting the wrist itself on the bat (the old way) ran the bat through the glove cuffs and made it look like part of the forearm. **The bat never leaves his hands**: if a pose puts a grip further from its shoulder than arm + `GRIP.reach` (0.08), `apply` draws the bat back toward that shoulder by the difference (picture only - outcomes come from the aim). Poses should not rely on it: the bunt and the swing reach with the body first (below), so it only trims the wildest chase pitches.
- **Stance** (`batterPose`, `KNOB_STANCE` [-0.55, 3.82, 0.95], `BAT_STANCE` yaw -1.5 / pitch .76, `WEIGHT_BACK` .12): knees flexed (hip 2.72), chest fairly upright (torso .18 + pelvis .12 rad), weight sitting on the back leg (pelvis shifted back, rocking a little), hands relaxed in front of and a little below the back shoulder and back from the face, lead elbow down across the chest, back elbow folded down under the hands (a knob close to the back shoulder folds that arm straight up over the head), bat laid back ~45 deg; not frozen: the hands drift in a small slow loop and the bat waggles. Owner (round ten): the old hands were "too stiff and close to his face". The swing starts from the stance (bat yaw / pitch, weight shifting from the back leg to the front) and reaches the same contact position as before.
- **Reaching** (`REACH` in poses.js): for a ball out over the plate (forward of `awayFrom`) or low (under `lowFrom`) he strides toward it, shifts his hips and leans out over the plate and sinks - full at contact, easing off over the first half of the follow-through. Before this, every outside pitch put the bat beyond his arms at contact (hands up to 0.6 ft off the bat). Measured with a throwaway in-browser check over whole swings (bat vs head, and how far the rig had to pull the bat in): at contact the bat is where the swing put it to within 0.01 ft at the nine zone spots (in / middle / away x low / middle / high); on the wildest chase pitches (1.2 ft off the plate and very low or high) the rig still trims 0.1-0.2 ft. Head clearance 0.19 ft.
- **Swing** (`batterPose`): load, rotation, contact; the follow-through is keyframed (`FOLLOW`: extension toward the pitcher, the bat climbs past the lead shoulder, high finish behind the head) so the bat never passes through the body - measured clearance ~0.4 ft from head and torso for every pitch location (a throwaway in-browser measurement: bat segment vs head sphere / spine points). Re-measure after touching `batterPose` or `FOLLOW`.
- **Pitching** (`pitcherPose`, round eleven; owner: "very non smooth ... looks like he is throwing with the wrong hand" - the hips and shoulders used to coil and unwind the LEFT-hander's way, and mid-delivery hand targets were out of the arm's reach so it snapped straight): one keyframed timeline (`P_BODY`, `P_FOOT_L/R`, `P_HAND_L/R`, poles; constants in `PITCH`) from the stretch - side on with the glove shoulder to the plate (pelvisYaw < 0 = closed), knee up, hands break at .44 (the ball goes to the throwing hand over `PITCHER_BALL_TO_HAND`), stride, foot strike with the arm cocked at .72, hips then shoulders open, release (hand keys .93-1.45 are offsets from the real release point, so every arm slot reaches its own), follow-through outside the front knee, a fielding stance, then five steps back up onto the rubber into the set (`pitcherSetAfter(dur)` s after release; the walk keeps a pace of at least `walkDur`). Phase p = u in the windup and 1 + seconds / windup length after it, so nothing hitches at the release. `actors.pitcherPoseUpdate` remembers the last pitch (`st.lastPitch`) so the walk back carries on into 'ready', and a windup that starts before he is set cross-fades. A high slot stands him taller (`slotTall`); measured: the hand reaches every release point (within 0.03 ft for the rookie curveball). Check with a throwaway page that renders `pitcherPose` at many phases from several angles.
- **Running** (`runPose`): ground contact `duty` (0.5 jog -> 0.33 sprint) moving back at exactly the running speed (`L = speed * duty / cadence`, no sliding feet), heel kick, knee drive, landing nearly under the hips, hip dip on each landing, bent arms pumping opposite to their own leg. `runCadence` is shared with every runner/fielder.
- **Leaving the plate** (`actors.batterGoes`, `batterRun`): the batter stays in his finish at the plate (bat in hand) until his run really starts - a batter who will be out at first starts a touch later than `batterStart` - and his first strides blend out of the exact pose he had there (`st.platePose`) with his hands from where they really were (`Person.gripHands`, recorded every frame), easing out over a quarter second or the first few feet. (He used to drop the bat, stand up straight for a quarter second and then jump into his run, with a 2 ft hand pop.)
- Infielders' ready position (`fielderReady` 'IF'): down low (hip 2.42), back fairly flat, glove out in front open and low, throwing hand beside it, eyes up on the hitter. Outfielders stay more upright.
- Bunt stance (`buntPose`; the top hand slides up toward the label; round ten, owner: "bending in odd places"): squared like a real bunter - feet turned to the pitcher (`footLYaw` / `footRYaw`, new pose scalars the rig applies to each foot), knees straight ahead over the toes, hips (`pelvisYaw` 1.3) and shoulders turned together (no twist at the waist), back fairly straight, and his whole body `BUNT_BACK` (1 ft) behind the bat so it is out in front of him with his arms reaching to it. **Knee directions (`kneeL` / `kneeR`) are in the HIPS' frame** (+z = the way the hips face), not the field's: the old bunt used field directions on turned hips and pushed the knees out sideways (the frog-legged look). He goes to the bat with his body - for a low bat he sinks right down (up to a crouch at the shins) with only a little forward bend, for one out over the plate he shifts and leans toward it, for one out front he shifts toward the pitcher - and keeps his eyes up. Owner: the bat used to detach from his arms when the aim went far (hands up to 1.5 ft off the bat on a low bunt); now 0.00 everywhere in the reachable aim area. Slides, dives, catches, throws as before. Renderer rules: facing only re-aims with a reason, every pose change cross-fades (`crossfadePose`); the catcher comes out of his crouch to throw.

## Conventions
- Put every tunable number in `src/config.js` with a plain-English comment. No magic numbers in logic.
- Logic modules must not import three.js or touch the DOM.
- Timing must never depend on frame rate: use engine time and `swingPressed(sinceUpdate)`; physics is precomputed at fixed steps.
- Renderers read engine state; they never change game outcomes. Randomness in outcomes comes only from the engine's seeded rng.
- After changing physics/fielding/contact/runner numbers: `npm test` and `node scripts/sim.mjs 100 30 pro`, compare with the baselines.
- QA hooks: `?mode=quick|derby|practice&bot=1&sd=25&seed=7&tod=night`; `?guide=0` / `?ring=0`; `window.__app.tick(dt, render)`; `app.startSeasonGame()`; engine overrides listed above. Menu QA: `app.openMenu('modes'|'season'|'standings'|'roster'|'shop'|...)` after putting a league in `app.prog.data.season` (`newSeason(null, { team, seed })` through `await import('/src/game/season.js')` in the dev server).
- Commit messages: clear, one topic each. Text the owner sees is labels only.

## Known issues and unfinished ideas
- **Feel is untested by the owner** for everything in the third round (League difficulty and prices, the new stance / delivery / tag animations, the slower windups and pace, the new menus). All are plain numbers in `config.js` or CSS tokens.
- **League:** a half-played game is saved at every pitch and resumes at the same pitch; it only counts when it is finished. A star bought from another team stays on that team's displayed lineup. Only your own club's stars and generated role players have ratings; CPU teams have one strength number. No custom players or skill points (the owner said buying players is enough). The computer never steals and its half-innings are simulated (no fielding for you). Player ratings affect your batters only; CPU teams have one strength number.
- **Only the lead runner can be thrown out on a steal or doubled off**; no pickoffs or rundowns. Runners are sent by tapping a lit base (hits, groundouts, after a catch to tag up); there is no call-back button (a sent runner turns back by himself when the throw will beat him).
- **Round six**: feel of the runner orders, the parks (Fenway's Monster, Coors' air) and the real-name ratings is untested by the owner. Real stat lines are last season's as remembered at the time of writing (no network here) - correct them in `MLB_TEAMS` if one is off; ratings follow by themselves.
- **Round five (owner: "batting is too hard")**: lower camera, pitch pace, an earlier and sharper guide, a bigger contact window with a separate sweet zone, a bigger ball with a longer streak, the swing animation through the aimed spot. Measured with `feel.mjs` (see Commands); feel is untested by the owner. Steals are a little easier than the measured rates above (a pitch takes longer to arrive).
- **Umpire recordings**: every call has at least one take except `ball4` (ball four uses `ball`). Adding more takes makes it less repetitive.
- **Real-device performance was never measured** (this sandbox renders in software). The sky light adds one small PMREM bake per time-of-day change.
- **By design, the player only bats.**
- **Round seven**: feel of the new difficulty, hit by pitch, home / away and the park looks is untested by the owner. A runner on first still rarely takes third on a single by himself (~10% after the deep clean, MLB ~28%: he would need a secondary lead, which would also change steals). Double plays are a little too common (62% of chances, MLB ~45-50%) and the runner on third scores on fewer grounders than in the majors (27%).
- **Round nine**: feel of the tap-a-base diamond and of runners who hold unless forced is untested by the owner (a runner on second no longer scores - or even moves - on a single unless you tap). (The smoke test used to fail on a Mac with a real graphics chip because Chrome logs a graphics driver performance notice, "GPU stall due to ReadPixels"; `scripts/smoke.mjs` now ignores only that kind of driver notice.)
- **Round eight**: with no automatic extra bases, a player who never sends runners scores less (sloppy bot Pro: win ~68%, 3.4 runs; All-Star ~50%) - realism.mjs's "runner on second scores on a single" is 0% by design. Real infield hits (slow rollers, balls deep in the hole) are missing: the old ~3% were bogus chopper plays.
- **Runner speed**: 30.2 ft/s is an elite big-league sprint (average ~27): home to first takes 4.0 s (MLB ~4.3). Kept on purpose - the game is balanced around it.
- **Nothing else is queued.** Further work comes from the owner's playtest notes.

## Working on the Mac or in the cloud sandbox (things that cost time before)
- **On the owner's Mac** (Claude Code in the terminal, not the cloud sandbox): Node, npm and `gh` come from Homebrew (`/opt/homebrew/bin`, `gh` is logged in - use it for Actions runs). `npm ci` works as is (the lockfile has every platform's build helper); "Cannot find native binding" from vitest/vite only means Node is older than 22.12 (rolldown's minimum) - use Homebrew's Node. Real Chrome is at `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` (pass it as `CHROME_PATH`). Always `git fetch` and start from `origin/main`.
- **Never use `pkill -f` / `pgrep -f` with a pattern that also appears in the same shell command** - it kills the shell itself. Find a dev server with `pgrep -x node` and check `/proc/<pid>/cmdline`. If the container restarts, the dev server is gone: `nohup npx vite --port 5173 --strictPort &`.
- In the cloud sandbox there is no `gh` CLI: use the GitHub MCP tools for Actions runs and checks there (on the Mac use `gh`). Git push works from the shell.
- Headless Chromium is at `/opt/pw-browsers/chromium` (use `playwright-core` with `executablePath`; never run `playwright install`). `page.evaluate` takes ONE argument. In tests collect problems and assert once; long simulation tests need an explicit timeout.
- `ffmpeg` is not installed by default (the 3 ffmpeg tests skip). The live site is blocked by the network policy.
- The smoke test builds several variants into temp folders; a scenario's folder name must not clash with another's.
- Practice's lineup[0] may be left-handed and the practice pitcher may be a lefty: set `settings.hand` and check `engine.pitcher.hand` before judging animation screenshots.
