# CLAUDE.md - Sandlot

Browser baseball batting and pitching game ("spiritual successor to the old doodle baseball game", far more polished). **Vite + vanilla JS + three.js.** Everything (textures, sound effects, people, crowd) is generated in code - the only asset files are the umpire's recordings (`public/sounds/umpire/`). The owner does not code: they judge by playing, so keep commands and explanations plain-English and never leave TODOs.

Modes: **League** (called Season in the code and the save: pick one of the 30 big-league clubs with their REAL names, colours and best hitters - personal use only, said in Credits - and play your 4 division rivals plus 4 teams of a neighbouring division, 6-inning games, standings, playoffs and a World Series, coins, a shop, a rated roster; you always bat in the bottom half), **Quick Game** (3 innings vs the computer, extra-innings runner on 2nd, walk-offs), **Home Run Derby** (10 outs, batting-practice pitches), **Practice** (pick the pitch; runners stay on base and runs are counted, no outs). Three levels: Rookie, Pro, All-Star. In Quick Game and League the player bats AND pitches the computer's half (round fourteen: aim a dot, tap a shrinking ring; your fielders make the plays by themselves; **Sim** finishes a half); Practice has a Bat / Pitch switch; the Derby is batting only.

## Commands
- `npm run dev` - dev server (http://localhost:5173)
- `npm run install-app` (Mac) - builds the game and installs `~/Applications/Sandlot.app` (`scripts/install-mac.sh`): a copy of `dist/`, a tiny Python web server on 127.0.0.1:48765 and a launcher that opens it in its own Chrome window (`--app`, own profile in `~/Library/Application Support/Sandlot`, so saves survive updates). Works offline. Run it again after pulling to update the owner's copy.
- `npm test` - Vitest (`tests/*.test.js`, pure logic, no browser)
- `npm run build` - production build to `dist/`. The base path comes from `scripts/resolveBase.mjs` (see Deployment). `vercel.json` holds the Vercel settings.
- `npm run smoke` - (after a build) serves `dist/` under a `/<repo>/` sub-path and drives headless Chrome: must reach the title screen and survive a real click-through (Settings with a volume slider, Credits, Esc back twice, Play, how-to, a setting, Quick Game, pause, the zone / pitch-guide / ring switches, one tap on Quit only arms it, resume). Console warnings count as failures. Eight scenarios (the click-through uses the `.tile[data-mode=quick]` tile): (1) built game reaches the title, (2) menus with real clicks, (3) Vercel-style build served at `/`, (4) default build (`./` base) served from another folder, (5) a build made for the wrong base served at the root of a non-GitHub host -> readable error that does not mention GitHub, (6) WebGL blocked -> the "couldn't start 3D graphics" screen, (7) the raw un-built source -> the "game files didn't load" screen, (8) a pretend recordings folder (`SANDLOT_UMPIRE_DIR`) -> files found by the build, downloaded after the first click, played, a call without a file is silent, and nothing 404s. `CHROME_PATH=/path/to/chrome` picks the browser (in this sandbox `/opt/pw-browsers/chromium`; CI uses the runner's Chrome).
- `npm run sim` / `node scripts/sim.mjs [games] [timingSdMs] [difficulty]` - headless bot playtest with stats (win %, AVG, HR, outcome table by contact grade; the computer's halves are pitched by the bot's `average` person: runs per half, K / BB / HBP per batter, pitches per half). Use it after changing physics/fielding/contact numbers.
- `node scripts/pitchfeel.mjs [halves=600] [new|average|good] [level]` - how PITCHING feels: a simulated person (`PITCHERS`: `new` ring tap sd 75 ms, aim shake .2 ft, sometimes the wrong pitch; `average` 50 ms / .12 ft; `good` 30 ms / .07 ft, mixes speeds; the aim policy is `bot.js` `chooseTarget`) pitches fresh computer half-innings through the real engine. Prints runs / H / BB+HBP / K / HR per half next to the target, pitches per half, ring grades, chase %, contact %, K / BB / HBP per batter and the referee's verdict on every ball in play. `--baseline` prints the recorded targets (`scripts/pitchfeelTargets.json`: the old simulated half, by level and by League club rating). `PITCH_BANDS=1 npx vitest run tests/pitchfeel.test.js` checks the bands (opt-in: ~13 min on the Windows PC; without the variable only the referee check runs; 400 halves, seed 5): average within +-20% of the target on every level, Rookie < Pro < All-Star, good <= .75 x average and new >= 1.15 x average on Pro, Pro K 20-35%, walks < 12%, no referee problems.
- `node scripts/pitchmix.mjs [pitches]` - where the computer pitcher throws, per difficulty.
- `node scripts/hrrate.mjs [swings] [derby|quick]` - home run % for perfect and good swings by level. Derby targets: perfect ~70-85%, good ~25-40%; `tests/hrrate.test.js` guards the bands. Derby-only batting help lives in `modes.derby` and reaches `computeContact` through `derbyBatting(cfg)`.
- `node scripts/feel.mjs [swings] [new|average|good] [quick|derby]` - how batting feels to a PERSON: a simulated player follows the pitch guide with a human reaction delay (`react`), hand shake and timing spread (`PLAYERS`) and swings at hittable pitches through the real swing, collision, flight and fielders. Prints contact % / miss % (and why) and fair / hit / HR per swing per level. `tests/feel.test.js` guards it. Round-five numbers (miss %, new / average / good): Rookie 8 / 3 / 0, Pro 27 / 12 / 3, All-Star 60 / 33 / 13; HR per swing on Pro 2 / 5 / 10%.
- `node scripts/guidecheck.mjs [pitches]` - how readable the pitch guide is per level, at the moment the batter must DECIDE (`timing.decideTime` before the swing must start). `node scripts/guideqa.mjs <dev-server url>` checks it in the real game.
- `node scripts/landingqa.mjs <dev-server url>` - the landing ring in the real game (spot vs where the ball lands, shrink, hide, switch).
- `node scripts/groundcheck.mjs [plays]` - thousands of ground balls through the planner and the referee (`src/game/playAudit.js`): every out must have a fielder ON the bag WITH the ball before the runner. Must say "no problems". `node scripts/groundqa.mjs <dev-server url>` measures the picture at the moment of the out.
- `node scripts/wallcatch.mjs [balls] [bandFeet]` - catch rate on catchable fly balls near the wall (must be 100%, `tests/wallcatch.test.js`). `node scripts/wallqa.mjs <dev-server url>` checks the picture.
- `node scripts/wallcheck.mjs [plays]` - any fielder outside the ballpark (`tests/wall.test.js`).
- `node scripts/tune.mjs [samples] [sdMs] [difficulty]` - hit/out/HR rate by batted-ball type.
- `node scripts/realism.mjs [balls] [seed]` - thousands of batted balls in every base / out situation through the real planner, next to rough big-league numbers (who fields, who covers second, double plays, the runner on third, sac flies by depth, extra bases on hits) plus the referee's verdict. Current: DP 62% (MLB ~45-50), 1B takes it himself 92%, runner on third scores on grounders 27% (MLB ~55-65), sac flies medium 98% / deep 100%, runner on second scores on a single 53% (MLB ~60), first to third 10% (MLB ~28), runner on first scores on a double 42%.

### Coordinates (used by every module)
Feet. Origin = back tip of home plate. `+x` = right-field side (screen-right from behind the plate), `-z` = toward the pitcher / center field, `+y` up. Spray angle 0 = center, negative = left field. The camera sits behind the plate at `+z`. Person-local axes: `+z` = the way they face, `+x` = their LEFT hand. Left-handed batters and pitchers are the same figure mirrored (`root.scale.x = -1`); their jersey artwork is pre-flipped about the FRONT of the shirt (u = 0.25).

### Logic (`src/game`, `src/physics`)
- `physics/field.js` - bases, fence curve, fair/foul test, grandstand profile, the ballpark outline for the wall code, the dugouts. **Ballparks**: `setPark(id)` (a key of `config.parks.list`) rewrites `CONFIG.field.fencePoints` / `fenceHeight` / `physics.dragK` and rebuilds the outline; `fenceHeightAt(spray)` (walls vary: Fenway's Monster), `currentPark()`. Sandlot Park is the default and what every test assumes (`tests/parks.test.js` switches and resets). The app calls `S.setPark` (render/scene.js: throws the stadium away - `disposeTree` - and builds it again) before every game: League = your club's park, else `settings.park` (Play screen **Park**), a resumed Quick Game keeps its park.
- `physics/pitch.js` - `buildPitch`: a constant-acceleration path solved to hit a chosen spot at the timing plane. `pace` (`difficulty.<level>.pitchPace`): the ball takes that many times longer to arrive than a real pitch at the speed shown (round five: easier to read; the speed shown, the timing windows and the exit velocity are unchanged). `zoneRatio` = how far a spot is from the middle of the zone (1.0 = the edge).
- `physics/ballistics.js` - `simulateBattedBall`: fixed-step (1/240 s) flight with gravity, drag, lift, hook, bounces, rolling, wall, stands. Also `judgeFairFoul`.
- `game/timing.js` - timing windows and `resolveSwingTimes`. **Error = bat time - ball time (ms)**.
- `physics/bat.js` - the bat-ball collision: `collide` / `hitBall` (an impulse model: restitution, friction capped at mu x the normal impulse, spin from the off-centre impulse; `bat.*` in config) and `describe` (exit velocity, launch, spray, backspin, sidespin). Offset `u` = how far the ball's centre is above the bat's (share of ball + barrel radius): u > 0 = bat under the ball (fly ball, backspin), 0 = line drive, < 0 = grounder / topspin.
- `game/contact.js` - `contactPoint(flight, tHit, tBarrel)` (the ball where the bat meets it, on the swing plane; the ball's velocity is scaled back up by `flight.pace` so the bat feels the pitch's real speed), `contactWindow(level)` (how far from the sweet spot the bat still TOUCHES the ball: up / tip / handle, plus `sweet` = `difficulty.<level>.sweetSpot`, the smaller part that decides how it comes off - beyond it inside the window the bat only gets a piece of it; `scaleWindow` for the Contact rating and `modes.derby.windowGrow`), `batOffset`, `computeSwing(i)` (aim + ball + timing -> the collision; misses report `under` / `over` / `end` / `hands` / `timing`; timing sets bat speed and the barrel's heading: early pulls, late goes the other way, `pullBias`), `derbyBatting()` (`evBonus`), `computeBunt` (the bunt also reads where the bat is: on top of the ball = down, under it = popped up). The engine's `batAim` ({x, y} on the plane over the plate, `setBatAim`, clamped to `swing.reach`) is locked at the press.
- `game/fielding.js` - `planPlay`: given the ball flight + runners, decides catch / groundout / hit / extra bases / double play / sac fly / error and returns a **plan** (fielder paths, throws, carries, loose-ball segments, runner moves, events, `endTime`). Deterministic. Inputs beyond the ball: `errorRoll` / `errorScale` (errors), `running` (runners going with the pitch), `speeds` (each runner's speed factor). `planSteal` plans a stolen-base attempt (no ball in play). Module state (`RUN`, `SPD`) is set only while those run.
- `game/rules.js` - counts, outs, walks, force advancement, `applyPlay` (results incl. `sacBunt`, `error` - an at-bat, not a hit, charged to the fielding team in `g.errors`), `applySteal`, innings, extra innings, walk-offs, line score.
- `game/pitcherAI.js` - what to throw and where ('heart' / 'edge' / 'chase' / 'waste' odds per level, shifted by the count; `o.arsenal` = draw types only from that pitcher's pitches - fastball / sinker `pitch.arsenalFast` .45, the rest split, heater only when listed; `o.intended` = the spot he aims at, without command scatter, for the auto pitcher).
- `game/pitching.js` - YOUR pitch (pure): `ringTiming` (ring time x Control `pitching.control` / pitch type `ringSpeed` / fatigue; meets the dot at `ring.hitAt`), `gradeTap` (ms off -> perfect / good / ok / wild; no tap = wild), `throwPitch` (speed from Velocity `pitching.velo` + the type's `speedDelta`, break from Stuff `pitching.stuff`, the grade's `speed` / `brk` / `miss`; early = up and arm side, late = down and glove side; WILD: `hang` (pulled toward the middle and up, little break) or sail), `fatigue` / `pitchCost` / `staminaMax` (`pitching.stamina`), `pitchTopMph` (what the buttons show), `pitcherStuff`, `isPainted`. ### Fielding, errors and outs
- `game/fielderMotion.js` is the ONE movement model (`covered`/`timeToCover`, `planRun`, `planDiveRun`, `Mover`). What the planner promises is exactly what is drawn.
- **The third out ends the play** (`endInningStop`): runners still going ease up and stop; no `safe` call for a base never reached.
- **Covering a base** (`coverOptions`): an out at a base only exists if somebody is on the bag with the ball before the runner (throw timed to the cover man, or the fielder carries it). Options: `tag` (seconds to tag a runner who is not forced - steals use `steal.tagTime`; home always `fielding.tagTime`), `coverStart` (steals: the cover man broke when the runner went). Force plays, double plays, hit plays, steals and doubling a runner off all use it. `auditPlan` (tests/groundouts, tests/steal, tests/errors) checks every out, including on caught balls and runners going back (`retreatArrival`).
- **Errors** (`fielding.errors`, x `difficulty.<level>.errorScale`, x `hardFactor` on a smash / dive / leap): a bobbled grounder (`bobble`) or a dropped fly (`dropFly`). The ball pops loose (`plan.looses` segments, drawn by `actors.ballInPlay` kind 'loose'), the fielder chases it (`chaseLoose`), then `finishHit` gives the runners what the delay allows. `plan.result = 'error'`, `plan.error = { pos, kind, t }`, event `error`. Decided by one seeded roll per ball in play (none in the Derby, none without a roll). ~1 error per 100 balls in play.
- **Who makes the play** (round three): a first baseman who has the ball near his bag walks over and steps on it (`cover.firstSelfDistance`, `firstSelfBonus`); on a thin force play the sure out at first wins (`fielding.thinForce`, `thinForceGain`); both outfielders break for an outfield ball and only one makes the catch (`chaseShare`); outfielders react slower (`reaction.OF` .52) and fewer balls are caught.
- **Tags**: `coverOptions` marks an option `tagged` when the runner is not forced (steals, home, runners on the bases); `planOut` writes `tag: true` on the `out` event. The picture (`actors.computeFielderPose`) gives every receiver of a throw a catch pose and, on a tag event, sweeps the glove down onto the runner (`tagOut`).
- Dives, the wall, catching fly balls at chest height, leaps at the wall: unchanged from before (see `findAirCatch`, `planDiveRun`, `wallBrake`, `CATCH_SETTLE`). Do not go back to "catch at the first reachable moment".

### Base runners (game/runnerMotion.js)
- ONE model for the planner and the picture: `runnerProfile(from, to, kind, cfg, spd)` (route with rounded corners + speed profile; `spd` = the runner's speed factor), `runnerArrival` / `runnerFinish`, `runnerState(move, t)` (moves carry `tStart`, `spd`, `back`, `backAt`, `stopAt`). Leads: `runner.lead` 9 ft, `runner.leadSecond` 18 ft (these shorten every runner's trip; `tests/runnerMotion.test.js` allows for them).
- **Going back** (`retreatState`, `retreatArrival`): a runner who went with the pitch runs on until `backAt`, pulls up, turns and runs back to the bag he left (not his lead spot). Used on fouls (`steal.readFoul`), caught balls (line drive: when it is caught; fly: `steal.readFly`) and when he ends up holding. On a caught ball one going runner may be doubled off (`runnersGoBack`), through `coverOptions`.
- **Steals** (`config.steal`): jump `steal.jump` + `jumpSd` after the windup starts; catcher exchange `steal.transfer` x `difficulty.<level>.catcherArm` (+ `dirtExtra` for a pitch in the dirt); throw to the lead runner; out only if the ball is on the bag + tag before him; no throw when hopeless (`noThrow`). Measured success (steal of second): Rookie ~88%, Pro ~76%, All-Star ~58%; of third a little lower (`qa-output`-style measurement: steal attempts through the real engine with no swings).
- **Reading the play**: on a grounder runners go at once (`runner.read`); on a ball in the AIR (`fielding.airLegs`, fewer than two outs) every runner does exactly the same whether it will be caught or not until it is caught or comes down (`plan.airRes`): first / second go `runner.halfway` of the way (a `half` leg) and wait, third - and second on a ball coming down past `runner.tagDepth` - goes back to the bag to tag up (`tagBack`), on a line drive a step or two (`halfwayLine`); then they react in `downReact`. With two outs they run on contact. Slides come from `actors.wantsSlide` (any out or safe call at a base from second on).
- **Runner orders (round six, simplified in round nine)**: on their own runners only move when FORCED (`runner.freeAdvance` false: `finishHit` holds a free runner, `advanceOnGroundout` and the runner-on-third break in `tryInfieldOut` only move him when he is going with the pitch; true = the old rule, a free runner takes the next base when safe); the batter stops at first (on a ball an outfielder fields runners ROUND their base, `move.round`), and NEVER an extra base by themselves (`runner.autoExtra` false; with true: one more when safe by `runner.autoMargin`, `m.auto`). A runner you sent who would be tagged sees the throw (`runner.retreatRead` after it is let go) and turns back to the bag he left when it is free and he beats a throw there (`plan.retreated`). `i.orders` = [{ base, t, from, back }]: a plain order sends the runner heading for `base - 1` on to `base` (a runner ahead in the way goes too), `back` calls a runner you sent to `base` back to `base - 1` (not a forced runner, not with a runner behind him going there). The planner keeps a RECORD per runner { from, to, legs, sent, sentTo, recalled, forced, lockAt } (`fielding.makeRecords`, `applyOrder`, `recToMove`); legs change through `runnerMotion.extendLegs` / `backLegs` (leg kinds `run` / `round` / `half` / `resume` (from where he is, with `v0`) / `reverse` (brakes, turns, runs back to a bag) / a run `fromBag` with a rocking start `v0 = tagRoll` for a tag-up). `plan.send = { from: runner.sendFrom, by, decide, res, pre, post }` on EVERY ball in play (homers and fouls too): `sendOptions(plan, t)` gives the tappable bases ({ base, from, kind: 'send' | 'back' }) from `pre` (before `res`, identical for a catch and a drop) or `post`. Hits (`finishHit`): orders in the air, then each runner's base at `airRes`, then later orders, then the auto step; the throw goes for the lead SENT runner it can beat as things stood at `decide` (= `runner.sendLead` before the fielder is ready); `by` = `sendAfter` after he is ready; a runner sent after `decide` is chased by the live defense (`liveDefense`, round twelve) from whoever has the ball. Caught balls (`caughtRunners`): at the catch everyone off his bag goes back (`backLegs`), a runner you sent before it can be doubled off (an appeal: no tag), the man on third (and second on a deep one) tags up by himself if it is safe, and after the catch you can send runners to tag up until `tagWindow` - one throw: doubled off, else at the lead tag-up runner (else a late throw home). Groundouts (`groundoutOrders`): orders up to the last out shape the play, later ones go to the live defense. Fouls: a sent runner goes and comes back. **Tag outs** (`tagRunner`): the out is made as he slides in (`arrive - runner.tagLead`), the man covering the bag stops ON it (`addMove` `stop`) and stays until the tag (`fielderFreeTime`), the runner walks off to the third-base dugout (`move.walkOff`, `runnerState` -> `walkOffState`), the play lasts `runner.outLinger` after it, `plan.outNote` = { base, from } and `plan.sentOut` feed the banner (*Out at 2nd*, *Runner out at home*, *Doubled off 1st*). Engine: `baseTargets()` / `tapBase(base)` (what the player and the bot use: `fielding.tapOptions` = the lit bases, a base only when nobody not out is heading for it, home always; re-plan, everything before the tap is identical); `runnerTargets()` / `runnerOrder(from, 'send' | 'back' | 'tag')` and `sendTargets` / `sendRunner(base)` still exist (tests) but nothing on screen uses them. HUD pad (`ui.setBasePad({ open, dots })`, dots carry `canBack`): the diamond only - `.bpbase` buttons (a big invisible tap target, `.open` = lit gold, drawn over the dots), coloured runner dots without labels (a ring on a runner you can call back), no text; size `--bp`. - A batter who is out at first runs THROUGH the bag. Home-run moves trot (a runner already going is matched onto the trot). Touch: the round **Swing** button (`.swingbtn`), a tap while the pitch is in flight, or a second finger. The batter's stance follows the bat's height, and the swing (`actors.batterAtPlate` -> `batterPose` contact point) puts the real bat's sweet spot exactly where you aimed on a miss, and on a hit where the bat physically had to be (the ball's centre minus the contact offset u x (ball + barrel radius)) - measured 0.00 ft off at contact.

### The players (rig.js, poses.js)
- Rig (round twelve: "make them look more like real people"): every body part is a smooth surface lofted through cross-sections (`anatomy.loft(rings, { seg, sub, cap, dome, key })`: rings `{ y, rx, rz, x, z, bumps: [{ a, w, h }] }`, angle 0 = front, +PI/2 = the figure's left; Catmull-Rom between rings; front of a jersey at u = 0.25; v runs up the part; cached by key - never dispose a cached geometry). `anatomy.js` builds the parts as `mergeParts` lists: `upperArmParts` (deltoid, biceps, triceps under a round-capped sleeve), `foreArmParts` (elbow point, brachioradialis, slim flat wrist), `thighParts` (baggy pants over quads, the side stripe as a ribbon on the surface), `shinParts` (calf high at the back, Achilles taper, cuff, bands that follow the sock), `torsoGeometry` (chest, shoulder blades, spine groove), `headParts` (a sculpted skull - chin, jaw, cheekbones, eye sockets, brow ridge - nose with wings and nostrils, ellipsoid lips, eyes set back under upper and lower lids with iris and pupil, eyebrows, ears with a rim; `facePaint` shades the sockets, warms the cheeks and nose tip and gives some players a beard shadow; `variant` from the jersey number varies jaw, nose and brow), `handParts('relaxed' | 'fist')` (palm with thumb pad, four fingers of three bones with knuckles, a two-bone thumb; batters keep the fist round `GRIP.point`; low detail = a mitten), `gloveParts('glove' | 'mitt')` (fielder's glove: padded heel, pocket, four fanned finger stalls, thumb, H-web, laces, strap, patch; catcher's mitt: round, padded rim, laces; the pocket stays where `gloveWorld()` puts the ball), `maskParts` (catcher / umpire cage mask: padded frame, curved bars, centre bar, throat guard, strap). The cap sits on the forehead and the batting helmet a little higher, so the eyes show. `mergeParts` carries UVs and an optional per-part `paint(x, y, z)` colour multiplier. **Surfaces** (full detail, `dl >= 0.9`): parts carry `mat` - `fabric` (woven normal map `textures.surfaceNormalTexture('fabric')`, also on jerseys), `skin` (roughness .6), `leather` (grain normal map; gloves, batting gloves, belt, cleats, mask), `hair`; `_merged(parent, parts, defaultKind)` makes one mesh per surface (under a group when there are several, so a scale applies to all); lower detail keeps the single vertex-colour material. Triangles per figure (day, full detail): batter ~18.6k, pitcher ~20.3k, catcher ~22.7k, umpire ~23.4k (were 13.2 / 12.2 / 13.3 / 13.2k), a fielder at .62 detail ~7.7k (was 5.8k); draw calls 22-28 (were 16-23). Joints, `DIM`, `GRIP`, poses and IK are untouched. Close-up QA: `qa-output/studio.mjs` (figures stood in front of the camera), `qa-output/rigshots.mjs`, `qa-output/swingshots.mjs` (throwaway, git-ignored). `scale` (height) scales the whole figure evenly and `build` only widens the pelvis, torso, yoke and shoulder spacing; `detail` lowers polygon counts for fielders/phones. Never let two parts' surfaces coincide (z-fighting).
- **Grip** (`Person.apply`, `GRIP` in rig.js): each fist closes ROUND the bat - the bottom hand `GRIP.bottom` (0.17 ft) up from the knob, the top hand touching it at `GRIP.top` (0.43; a pose can slide it up with `gripTop`, the bunt uses 1.05) - with the handle through `GRIP.point` inside the fist; the wrist turns so the bat lies across the fingers (index finger toward the barrel, back of the hand toward the elbow), solved in two passes (hand pointing back at the shoulder, then at where the elbow really went). Putting the wrist itself on the bat (the old way) ran the bat through the glove cuffs and made it look like part of the forearm. **The bat never leaves his hands**: if a pose puts a grip further from its shoulder than arm + `GRIP.reach` (0.08), `apply` draws the bat back toward that shoulder by the difference (picture only - outcomes come from the aim). Poses should not rely on it: the bunt and the swing reach with the body first (below), so it only trims the wildest chase pitches.
- **Stance** (`batterPose`, `KNOB_STANCE` [-0.55, 3.82, 0.95], `BAT_STANCE` yaw -1.5 / pitch .76, `WEIGHT_BACK` .12): knees flexed (hip 2.72), chest fairly upright (torso .18 + pelvis .12 rad), weight sitting on the back leg (pelvis shifted back, rocking a little), hands relaxed in front of and a little below the back shoulder and back from the face, lead elbow down across the chest, back elbow folded down under the hands (a knob close to the back shoulder folds that arm straight up over the head), bat laid back ~45 deg; not frozen: the hands drift in a small slow loop and the bat waggles. Owner (round ten): the old hands were "too stiff and close to his face". The swing starts from the stance (bat yaw / pitch, weight shifting from the back leg to the front) and reaches the same contact position as before.
- **Reaching** (`REACH` in poses.js): for a ball out over the plate (forward of `awayFrom`) or low (under `lowFrom`) he strides toward it, shifts his hips and leans out over the plate and sinks - full at contact, easing off over the first half of the follow-through. Before this, every outside pitch put the bat beyond his arms at contact (hands up to 0.6 ft off the bat). Measured with a throwaway in-browser check over whole swings (bat vs head, and how far the rig had to pull the bat in): at contact the bat is where the swing put it to within 0.01 ft at the nine zone spots (in / middle / away x low / middle / high); on the wildest chase pitches (1.2 ft off the plate and very low or high) the rig still trims 0.1-0.2 ft. Head clearance 0.19 ft.
- **Swing** (`batterPose`): load, rotation, contact; the follow-through is keyframed (`FOLLOW`: extension toward the pitcher, the bat climbs past the lead shoulder, high finish behind the head) so the bat never passes through the body - measured clearance ~0.4 ft from head and torso for every pitch location (a throwaway in-browser measurement: bat segment vs head sphere / spine points). Re-measure after touching `batterPose` or `FOLLOW`.
- **Pitching** (`pitcherPose`, round eleven; owner: "very non smooth ... looks like he is throwing with the wrong hand" - the hips and shoulders used to coil and unwind the LEFT-hander's way, and mid-delivery hand targets were out of the arm's reach so it snapped straight): one keyframed timeline (`P_BODY`, `P_FOOT_L/R`, `P_HAND_L/R`, poles; constants in `PITCH`) from the stretch - side on with the glove shoulder to the plate (pelvisYaw < 0 = closed), knee up, hands break at .44 (the ball goes to the throwing hand over `PITCHER_BALL_TO_HAND`), stride, foot strike with the arm cocked at .72, hips then shoulders open, release (hand keys .93-1.45 are offsets from the real release point, so every arm slot reaches its own), follow-through outside the front knee, a fielding stance, then five steps back up onto the rubber into the set (`pitcherSetAfter(dur)` s after release; the walk keeps a pace of at least `walkDur`). Phase p = u in the windup and 1 + seconds / windup length after it, so nothing hitches at the release. `actors.pitcherPoseUpdate` remembers the last pitch (`st.lastPitch`) so the walk back carries on into 'ready', and a windup that starts before he is set cross-fades. A high slot stands him taller (`slotTall`); measured: the hand reaches every release point (within 0.03 ft for the rookie curveball). Check with a throwaway page that renders `pitcherPose` at many phases from several angles.
- **Running** (`runPose`): ground contact `duty` (0.5 jog -> 0.33 sprint) moving back at exactly the running speed (`L = speed * duty / cadence`, no sliding feet), heel kick, knee drive, landing nearly under the hips, hip dip on each landing, bent arms pumping opposite to their own leg. `runCadence` is shared with every runner/fielder.
- **Leaving the plate** (`actors.batterGoes`, `batterRun`): the batter stays in his finish at the plate (bat in hand) until his run really starts - a batter who will be out at first starts a touch later than `batterStart` - and his first strides blend out of the exact pose he had there (`st.platePose`) with his hands from where they really were (`Person.gripHands`, recorded every frame), easing out over a quarter second or the first few feet. (He used to drop the bat, stand up straight for a quarter second and then jump into his run, with a 2 ft hand pop.)
- Infielders' ready position (`fielderReady` 'IF'): down low (hip 2.42), back fairly flat, glove out in front open and low, throwing hand beside it, eyes up on the hitter. Outfielders stay more upright.
- Bunt stance (`buntPose`; the top hand slides up toward the label; round ten, owner: "bending in odd places"): squared like a real bunter - feet turned to the pitcher (`footLYaw` / `footRYaw`, new pose scalars the rig applies to each foot), knees straight ahead over the toes, hips (`pelvisYaw` 1.3) and shoulders turned together (no twist at the waist), back fairly straight, and his whole body `BUNT_BACK` (1 ft) behind the bat so it is out in front of him with his arms reaching to it. **Knee directions (`kneeL` / `kneeR`) are in the HIPS' frame** (+z = the way the hips face), not the field's: the old bunt used field directions on turned hips and pushed the knees out sideways (the frog-legged look). He goes to the bat with his body - for a low bat he sinks right down (up to a crouch at the shins) with only a little forward bend, for one out over the plate he shifts and leans toward it, for one out front he shifts toward the pitcher - and keeps his eyes up. Owner: the bat used to detach from his arms when the aim went far (hands up to 1.5 ft off the bat on a low bunt); now 0.00 everywhere in the reachable aim area. Slides, dives, catches, throws as before. Renderer rules: facing only re-aims with a reason, every pose change cross-fades (`crossfadePose`); the catcher comes out of his crouch to throw.

## Conventions
- Put every tunable number in `src/config.js` with a plain-English comment. No magic numbers in logic.
- Logic modules must not import three.js or touch the DOM.
- Timing must never depend on frame rate: use engine time and `swingPressed(sinceUpdate)`; physics is precomputed at fixed steps.
- Renderers read engine state; they never change game outcomes. Randomness in outcomes comes only from the engine's seeded rng.
- After changing physics/fielding/contact/runner numbers: `npm test` and `node scripts/sim.mjs 100 30 pro`, compare with the baselines.
- QA hooks: `?mode=quick|derby|practice&bot=1&sd=25&seed=7&tod=night`; `?guide=0` / `?ring=0`; `window.__app.tick(dt, render)`; `app.startSeasonGame()`; engine overrides listed above. Menu QA: `app.openMenu('modes'|'season'|'standings'|'roster'|'shop'|...)` after putting a league in `app.prog.data.season` (`newSeason(null, { team, seed })` through `await import('/src/game/season.js')` in the dev server).
- Commit messages: clear, one topic each. Text the owner sees is labels only.
